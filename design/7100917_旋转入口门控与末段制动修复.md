# 7100917 旋转入口门控与末段制动修复

## 实测结论

7100916 的无线串口接收正常。日志明确记录了 `Q` 和后续 `R` 的 UART8 接收帧，命令未执行是旋转入口主动拒绝，不是按键丢失或串口卡死。

两次 90 度单转均完成，但存在近似对称的动态过冲：

- CW：IMU `0.0 -> 97.6deg`，视觉变化 `+96.4deg`，编码器估算 `+88.6deg`。
- CCW：IMU `97.6 -> 0.0deg`，相对变化 `-97.6deg`，视觉变化 `-96.4deg`，编码器估算 `-85.1deg`。
- 两次 IMU 最终误差均约 `7.6deg`，说明主要问题是末段制动和静摩擦下的保持能力，而不是单向符号错误。
- 第二次视觉稳定簇角度跨度达到 `12.0deg`。旧旋转入口要求“位置和角度同时稳定”，因此 `Q/R` 被长期拒绝。

## 7100917 修改

- MCU ID：`7100917`，模式3启动阶段：`ROT_POS_GATE_APPROACH40`。
- 旋转入口和自动序列的步间入口只要求：IMU就绪、视觉在线、视觉位置稳定。视觉角度稳定不再阻止启动。
- 平移采集原有完整视觉稳定门控保持不变。
- 旋转目标前 `20deg` 的末段速度由 `60` 降为 `40 counts/5ms`。
- 距目标剩余 `3deg` 时提前退出主动旋转，随后仍用原定目标航向进入保持，不把提前制动点当成新目标。
- `CAL_POINT` 同时打印 `angle` 与 `pos` 两套稳定标志。
- `R/Q/A/M` 被拒绝时新增 `ROT_START_BLOCK`，打印 state、IMU、live、位置稳定、角度稳定和帧龄。
- 未修改全局摄像头和第二摄像头。

1. `7 -> 2 -> R`：执行 CW 90 度，等到完整 `ROT_REC`。
2. `D -> R`：执行 CCW 90 度，等到完整 `ROT_REC`。
3. 两次都应能看到 `speed=80`，末段看到 `speed=40`，最终误差应小于 7100916 的约 7.6 度。
4. 再按 `Q`：执行 90 度往返。即使 `angle=0`，只要 `pos=1/6`、IMU和live正常也应启动。
5. 先不要运行 `A/AUTO16`。单转和往返通过后，再重新上电执行 `7 -> 2 -> Q` 复测；确认稳定后才进入 `A` 自动16条采集。
