## 2. 本轮实施顺序

1. 增加单个逻辑网格步的运动、停车、视觉排空和视觉稳定耗时观测。
2. 只在普通非严格、非环境切换网格步启用自适应停车。
3. PUSH 完成后优先复用本步已经取得的严格视觉确认；条件不满足时完整保留原有推后复核。
4. 构建模式 0/1/2/3，并恢复正式模式 0。
5. 先通过实车日志验证收益，再决定是否缩短视觉排空或进入固定滞后融合；本轮不一次叠加这些高风险变量。

## 3. 自适应停车

普通开放区、单边墙和走廊中的非严格网格步允许提前结束原固定 500ms 停车保持，但必须同时满足：

- 已停车至少 300ms；
- 三轮编码器速度绝对值均不大于 12 counts/5ms；
- 三轮位置环误差绝对值均不大于 12；
- IMU Z 轴角速度绝对值不大于 3deg/s；
- 上述静止条件连续保持至少 100ms。

500ms 仍是绝对上限和保底条件。任意一项不满足时不会提前结束。

以下上下文强制关闭自适应停车，继续完整保持 500ms：

- 箱子、炸弹或目标点八邻域；
- 箱子或炸弹 PUSH；
- 单边墙/开放区等环境策略切换节点；
- 物理短距 ALIGN；
- 开局格心重锚和原有严格确认流程。

## 4. 分阶段遥测

无线 UART8 遥测新增 `RUN_TIME`：

- `step`：当前逻辑网格步总耗时；
- `move`：编码器+IMU主体运动时间；
- `settle`：停车保持时间；
- `drain`：视觉旧帧排空时间；
- `stable`：稳定视觉帧聚类时间；
- `adaptive=en/used`：该步是否允许、是否实际提前完成停车；
- `still=ready/ms`：静止判定及连续稳定时间；
- `strict`：是否为严格位置上下文；
- `align`：该步已执行的物理短距修正次数。

插入 ALIGN 时，阶段耗时按整个逻辑网格步累计，便于判断时间究竟耗在主体运动、停车、视觉排空还是稳定帧等待。

## 5. PUSH 严格确认复用

PUSH 本身仍执行物体八邻域严格确认。动作完成后，仅在同时满足以下条件时复用该确认结果：

- 本步为 `strict_position`；
- 已获得完整严格稳定帧，数量不少于要求且至少为 6 帧；
- 严格确认均值相对目标单轴误差均不超过 20mm；
- 复用瞬间仍有新鲜有效位置帧，实时位置相对目标单轴误差也均不超过 20mm。

满足时直接完成原 `POST_PUSH_REANCHOR` 的稳定确认部分，并继续原有地图校验/动作提交逻辑。任意条件不满足时，仍进入原 `POST_PUSH_REANCHOR`，继续 1000ms 排空、6 帧/200ms 稳定确认和原有失败处理，不降低安全性。

遥测 `RUN_GUARD post_push[...]` 新增 `reused=1/0`。`reused=0` 不是故障，只表示走了原保守复核路径。

## 8. 实车验证流程

完整断电重启并下载标准 AXF，确认启动行包含：

`id=7100921 stage=ADAPTIVE_SETTLE_CONFIRM_REUSE`

首次保持 `STANDARD`，菜单流程：

`1 -> 等待 FULL_MAP/MAP_END -> 2 -> D -> 等待 PLAN_SUMMARY valid=1/current=1 与 PLAN_CHECK ok=1 -> B -> 3 -> E -> 等待开局格心复核进入 STEP_WAIT -> N`

先逐格执行数个普通路段和一个物体邻域/PUSH步骤，每次都等待重新进入 `STEP_WAIT`：

- 普通步骤应看到 `adaptive=1`；车稳定较快时可见 `used=1`，`settle` 约 300..500ms。
- 严格物体邻域/PUSH应看到 `strict=1 adaptive=0/0 settle=500ms`。
- PUSH 后若已有确认可复用，应看到 `reused=1`；若为 `reused=0` 并进入旧复核流程也属于正常保守行为。
- 若方向、停车、格心确认和推箱均正常，再按 `A` 完成剩余动作。

若出现异常，保留从该步前一个 `MISSION_EXEC` 到下一个 `STEP_WAIT/PAUSED/FAULT` 的完整日志，并直接回退到重点备份中的 7100920 源码和 AXF。

## 9. 后续推荐顺序

1. 用 `RUN_TIME` 实车统计普通、严格、PUSH和ALIGN各阶段耗时，确认本轮节省量与离群情况。
