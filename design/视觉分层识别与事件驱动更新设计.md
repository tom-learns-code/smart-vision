# 视觉分层识别与事件驱动更新设计

> 文档日期：2026-06-24  
> 状态：讨论总结与后续重构依据  
> 适用对象：OpenART 视觉层、视觉协议层及地图状态管理  
> 核心原则：状态分层、识别分频、输出合成、物理约束、事件驱动校正

---

## 1. 目标

当前视觉系统不应继续把墙、目标、箱子、炸弹和车辆放在同一张分类图中互相竞争。不同元素的空间精度、更新频率、运动规律和遮挡关系不同，应分别识别和维护状态，最后仅在输出时合成。

目标架构：

```text
摄像头图像
├─ 静态地图层：地板、墙体、目标点
├─ 动态物体层：箱子、炸弹
└─ 车辆姿态层：车头标记、车尾标记、中心位置、角度

FULL_MAP   = 静态地图层 + 动态物体层 + 车辆姿态层
POS_UPDATE = 车辆姿态 + 激活状态的动态物体
```

三层分别保存真实世界状态，不能因为输出画面叠加而互相覆盖内部状态。

---

## 2. 已确认的比赛规则

以下内容是比赛规则和实际游戏行为，不是视觉算法自行假设。

### 2.1 地图边界

- 地图大小为 `16×12`。
- 第一行、最后一行、第一列、最后一列固定为边界墙。
- 边界墙不可被炸毁。
- 箱子和炸弹都不能进入边界墙。

### 2.2 箱子

- 箱子可以被车辆推动。
- 箱子不能进入任何墙体。
- 箱子进入墙体时会被阻挡。
- 箱子进入目标点后可能被静态显示层遮挡。
- 不匹配的箱子进入目标点不会消失，仍需保留和跟踪。

### 2.3 炸弹

- 炸弹可以被车辆推动。
- 炸弹不能进入边界墙。
- 炸弹可以进入非边界墙，并被墙体遮挡。
- 炸弹进入目标点后也可能被静态显示层遮挡。
- 炸弹进入非边界墙并满足爆炸条件后，会改变静态墙体地图。

### 2.4 动态物体运动

- 箱子和炸弹每次运动只沿 X 轴或 Y 轴，不会斜向移动。
- 不允许连锁推动。
- 若车辆推动物体 A，而 A 前方存在动态物体 B，则 B 像墙一样阻挡 A。
- 不会发生“车辆推 A，A 再推动 B”的情况。

### 2.5 车辆推动规则

- 车辆推动箱子或炸弹时，车辆朝向可以是任意方向。
- `car.theta` 与推动方向没有必然关系。
- 车辆朝向不得用于判断是否正在推动、推动轴、推动方向或遮挡后的物体位置。

正确的推动关系主要来自：

```text
车辆中心位置变化
+ 车辆中心速度
+ 车辆与物体的相对位置
+ 物体的单轴速度
+ 碰撞和阻挡规则
```

车辆角度仅用于车辆姿态输出、导航控制以及车头车尾标记配对。

## 3. 分层状态模型

### 3.1 静态地图层

空间精度为一格：

```text
StaticCell {
    class: UNKNOWN | FLOOR | WALL | GOAL
    confidence
    candidate_class
    candidate_count
    last_verified
}
```

职责：

- 保存墙、目标和地板。
- 第一帧建立高置信初始地图。
- 后续只在强证据或明确游戏事件下修改。
- 不保存箱子、炸弹和车辆。

### 3.2 动态物体层

箱子和炸弹使用 `0.1格` 连续坐标：

```text
DynamicObject {
    track_id
    class: BOX | BOMB
    x
    y
    state
    confidence
    visible_fraction
    locked_axis
    move_direction
    estimated_velocity
    recent_positions
    last_seen
}
```

建议状态：

```text
FROZEN
ACTIVE
PUSH_CANDIDATE
PUSHING_X
PUSHING_Y
OCCLUDED
SETTLING
BLOCKED
EXPLOSION_PENDING
REMOVED
```

### 3.3 车辆姿态层

车辆独立高频识别：

```text
CarState {
    front_x
    front_y
    back_x
    back_y
    center_x
    center_y
    theta
    velocity_x
    velocity_y
    confidence
    last_seen
}
```

车辆层精度为 `0.1格 + 角度`，更新频率高于其他两层。

## 4. 第一帧初始化

第一帧允许使用较高计算量，但不同类别必须分开存储。

### 4.1 静态层初始化

- 对 `16×12` 网格进行高质量逐格扫描。
- 识别 `FLOOR / WALL / GOAL`。
- 使用密集采样、颜色置信度和必要的少量验证帧。
- 初始结果写入 `static_map_initial` 和 `static_map_current`。

### 4.2 箱子与炸弹初始化

- 初始箱子和炸弹位于标准格中心。
- 可以使用与静态建图相同的高质量整格扫描。
- 识别结果写入动态物体表，而不是静态地图。
- 动态物体所在格在静态层中应恢复其下方的地板状态。

初始时默认不存在动态物体与目标、墙体的遮挡，因此可直接按空地处理箱子和炸弹所在格。

### 4.3 车辆初始化

- 车辆离开基地后才会出现在地图中。
- 离开基地后不保证处于标准整格中心。
- 车辆必须完全排除出一格精度的静态建图。
- 车辆单独使用青绿标记、`0.1格` 坐标和角度识别。

当前阶段暂时忽略车辆离开基地后恰好覆盖目标点的特殊情况。

## 5. 更新频率与计算预算

| 层 | 空间精度 | 更新频率 | 主要算法 |
|---|---:|---:|---|
| 静态地图层 | 1格 | 首帧、低频或事件触发 | 逐格密集采样、强置信状态更新 |
| 动态物体层 | 0.1格 | 车辆附近中高频 | 局部 ROI、轨迹和物理约束 |
| 车辆姿态层 | 0.1格+角度 | 最高频 | 青绿组件、配对、滤波 |
| 全图审计 | 1格/低精度 | 极低频或主动请求 | 异常恢复和状态校验 |

获取整张摄像头帧并不是主要开销，主要开销来自对整图执行高密度分类。因此可以持续获取整帧，但只在必要区域进行高计算量分析。

## 6. 以车辆为中心的动态物体激活区域

箱子和炸弹不会自行运动，其状态变化通常发生在车辆附近。动态物体跟踪以车辆连续坐标为圆心激活。

```text
dx = object.x - car.x
dy = object.y - car.y
distance_sq = dx² + dy²
```

建议初始参数：

```text
进入激活半径：1.5格
退出冻结半径：1.8格
```

激活圆心使用车辆 `0.1格` 连续坐标，每帧随车辆同步移动，不对齐绝对整数网格。

### 6.1 ACTIVE

物体进入激活区域后：

- 在局部 ROI 中持续检测。
- 以上一帧位置缩小搜索范围。
- 更新连续坐标、置信度和可见比例。
- 检测推动轴、推动方向、遮挡和阻挡状态。
- 参与高频位置更新。

### 6.2 FROZEN

物体离开退出半径后：

- 停止视觉搜索，节约算力。
- 保留冻结前的稳定位置。
- 仍属于动态物体层，不能改写为静态类别。
- `FULL_MAP` 持续输出冻结位置。
- 高频更新包可不重复发送无变化对象。

### 6.3 激活迟滞

避免物体在圆形边界附近反复切换：

- 连续两帧进入后激活。
- 连续三帧离开且位置稳定后冻结。
- 刚被推动的物体延迟冻结。

---

## 7. 冻结位置计算

不能直接平均推动过程中的最后几帧，否则可能把物体冻结在两个格子之间。

推荐流程：

1. 检测物体速度低于阈值。
2. 收集最后 `3～5` 个高置信静止位置。
3. 使用中位数或截尾均值。
4. 若退出区域时物体仍在运动，保留最新高置信位置。
5. 仅在确认稳定于格子中心时，允许吸附到整格中心。

---

## 8. 单轴推动状态估计

箱子和炸弹只沿单轴移动，可用于降低视觉噪声和处理遮挡。

推动方向状态：

```text
STATIONARY
X_POS
X_NEG
Y_POS
Y_NEG
```

### 8.1 推动候选检测

使用以下证据：

- 车辆中心与物体的距离足够近。
- 车辆位于物体运动方向的后侧。
- 车辆中心速度与物体速度在推动轴上方向一致。
- 车辆和物体在垂直推动轴方向上的位置足够接近。
- 前几帧物体位移连续一致。
- 前方没有禁止进入的墙或其他动态物体。

明确禁止使用：

```text
car.theta
车辆车头方向
车辆朝向与运动轴的夹角
```

### 8.2 轴锁定

连续数帧确认后锁定运动轴：

```text
锁定 X 轴：
    更新 object.x
    object.y 保持推动前稳定值

锁定 Y 轴：
    更新 object.y
    object.x 保持推动前稳定值
```

锁定后，另一轴的视觉抖动不应进入状态估计。

---

## 9. 碰撞与禁止连锁推动

### 9.1 箱子碰撞

```text
下一位置进入任意墙体 -> BLOCKED，保持原位置
```

### 9.2 炸弹碰撞

```text
下一位置进入边界墙   -> BLOCKED
下一位置进入普通墙   -> 允许，进入 ENTERING_WALL / OCCLUDED
```

### 9.3 动态物体之间

若 A 的前方存在 B：

```text
车辆 -> A -> B
```

则：

- A 不能继续前进。
- B 不能因为 A 的接触而更新位置。
- 不允许两个动态对象重叠、交换顺序或同时被推行。
- 若视觉显示 A、B 同时沿相同方向移动，应降低该观测置信度并触发审计。

## 10. 静态层遮挡动态层

上位机的显示关系相当于静态元素位于动态物体上方：

```text
CameraImage = StaticLayer 遮挡 DynamicLayer 后的可见结果
```

典型情况：

- 不匹配箱子进入目标点后，箱子仍存在，但被目标部分遮挡。
- 炸弹进入目标点后被目标遮挡。
- 炸弹部分进入非边界墙时，墙内部分不可见。

内部世界状态不能因视觉遮挡而删除对象。

### 10.1 部分遮挡

- 根据静态地图计算理论可见区域。
- 使用完整物体模板匹配可见残片。
- 用上一帧位置和单轴运动约束限制搜索。
- `visible_fraction` 越低，视觉位置更新权重越低。
- 不把可见残片质心直接作为完整物体中心。

### 10.2 完全遮挡

- 依靠上一状态、锁定轴、车辆中心速度和碰撞边界短期推算。
- 车辆停止、离开推动关系或发生阻挡后立即停止外推。
- 不允许无限时间无观测推算。
- 只有明确游戏事件成立时才能删除对象。

---

## 11. 静态地图持续校正

第一帧高置信地图是初始先验，不是永久不可改变的真值。

建议状态转移：

```text
WALL    -> FLOOR    允许，主要由爆炸事件触发
FLOOR   -> WALL     通常禁止
GOAL    -> FLOOR    通常禁止
FLOOR   -> GOAL     初始化完成后通常禁止
UNKNOWN -> 任意类   允许
```

普通持续检测采用强证据迟滞：

- 新类别达到强置信度。
- 该格不存在动态遮挡。
- 连续若干次检测一致。
- 低于强置信阈值时保持原状态。
- 动态物体遮挡时暂停静态状态更新。

静态地图需要双向检测能力，但状态转移必须受比赛规则限制，不能自由互转。

## 12. 炸弹爆炸事件

静态地图采用缓存和事件驱动局部重建，不持续对全图做高强度识别。

### 12.1 爆炸候选条件

不能仅凭炸弹消失判断爆炸。应综合：

- 炸弹已进入或接近非边界墙。
- 炸弹运动轴和最后位置支持进入墙体。
- 炸弹连续若干帧不可见。
- 附近原墙体区域出现强地板证据。
- 当前不存在会导致误判的动态遮挡。

### 12.2 三阶段处理

#### 阶段一：推导

- 根据炸弹最后几个可靠位置和锁定运动轴推导爆炸中心。
- 可以测试推导中心及上下左右相邻中心。
- 边界墙永远不得列入爆炸清除候选。

#### 阶段二：候选地图与验证

- 从 `static_map_current` 复制 `pending_map`。
- 在候选爆炸中心周围暂时清除 `3×3` 非边界墙。
- 以爆炸中心建立 `5×5` 验证区域。

验证内容：

```text
内部3×3：
    验证原墙体是否出现强地板证据

外围一圈：
    验证爆炸范围外的静态结构是否保持
    校验推导爆炸中心是否偏移
```

被车、箱子或仍可见炸弹遮挡的格不参与否决。

#### 阶段三：原子提交

- 内部变化证据和外圈保持证据均通过后，提交 `pending_map`。
- 验证失败则保留原地图。
- 证据不足时保持 `EXPLOSION_PENDING`，后续帧继续验证。
- 只有提交成功后才从动态物体层删除炸弹并发布新 `FULL_MAP`。

### 12.3 地图版本

```text
static_map_initial
static_map_current
pending_map
map_version
```

连续爆炸必须基于当前有效地图更新，而不是每次回退到第一帧。

---

## 13. 爆炸后的扫描预算

爆炸候选出现时可以获取一张全图，但分类计算分级执行：

```text
5×5验证区域：
    高密度采样
    必要时连续两帧确认

其他区域：
    保持缓存
    仅做低强度异常检查

车辆层：
    保持高频更新

动态物体层：
    继续局部跟踪
```

验证通过后更新静态地图并发送 `FULL_MAP`。

---

## 14. 全图审计

局部跟踪是主流程，但需要低频或事件触发的全局审计。

触发条件：

- MCU 请求 `FULL_MAP`。
- 车辆位置突然跳变。
- 活跃动态物体连续丢失。
- 冻结物体与当前观测长期矛盾。
- 爆炸事件待确认。
- 地图重规划或人工校正。

全图审计用于恢复异常，不应替代常规局部跟踪。

---

## 15. 输出策略

### 15.1 FULL_MAP

`FULL_MAP` 是各层在发送时的合成快照：

```text
base = static_map_current
overlay boxes
overlay bombs
overlay car
```

合成结果不能反向写回任何层。

### 15.2 POS_UPDATE

高频位置更新主要包括：

- 车辆中心位置和角度。
- ACTIVE 状态的箱子和炸弹。
- 必要的对象状态变化。

FROZEN 对象无变化时不必重复执行视觉检测，可由缓存持续提供位置。

---

## 16. 推荐主状态流

```text
第一帧高质量扫描
├─ 建立静态地图缓存
├─ 初始化箱子和炸弹动态对象表
└─ 独立初始化车辆姿态

正常运行
├─ 车辆层持续高频识别
├─ 车周1.5格激活动态物体跟踪
├─ 车外1.8格冻结对象
├─ 单轴推动状态估计
├─ 遮挡时使用模板、历史和物理约束
└─ 静态层保持缓存

爆炸事件
├─ 推导爆炸中心
├─ 构建3×3候选清除区域
├─ 高质量验证5×5区域
├─ 验证通过后提交新静态地图版本
└─ 删除炸弹并发送更新后的FULL_MAP
```

## 18. 实现优先级建议

1. 建立三层独立数据结构，停止用一张分类图保存全部状态。
2. 完成第一帧高质量初始化和输出时合成。
3. 实现车辆中心驱动的 ACTIVE/FROZEN 动态物体状态机。
4. 加入单轴运动、墙体碰撞和禁止连锁推动约束。
5. 实现目标点及墙体遮挡下的动态对象保持。
6. 实现炸弹爆炸的 `3×3` 推导与 `5×5` 验证。
7. 加入低频全图审计和异常恢复。

## 19. 最终原则

```text
状态分层，而不是类别互相覆盖。
识别分频，而不是所有元素每帧全图扫描。
物理规则约束观测，而不是只相信颜色质心。
首帧建立先验，但允许明确事件修正静态地图。
遮挡不等于消失，只有确认的游戏事件才能删除对象。
车辆朝向只描述姿态，绝不参与推动方向判断。
```
