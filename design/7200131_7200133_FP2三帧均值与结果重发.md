# FP2 三帧均值与结果重发

## 本轮结论

- 上一轮数字 worker 已完成识别并生成合法 `fp2_last.bin`，说明分发、模型推理和结果落盘均正常；MCU 超时的剩余故障位于 worker 复位后的结果送达阶段。
- 正式识别改为多帧融合，降低单帧画面抖动、曝光变化和偶发误分类的影响。
- 本轮不修改全局摄像头和运动控制逻辑。

## 实现

### 二号摄像头

- 监听器 `7200131`：启动后读取当前会话的 `fp2_last.bin`，先等待 80 ms，再以 120 ms 间隔非阻塞重发 4 次。只重发合法、类型为 RESULT 且 session 与当前状态一致的帧；新会话会清除旧结果和重发状态。
- 图片 worker `7200132`：两个图片模型分别加载一次；每个模型连续采集 3 帧，对每一类别的概率逐项累加后求均值，再沿用原来的双模型 0.80 阈值融合规则。
- 数字 worker `7200133`：数字模型加载一次，连续采集 3 帧，对每一类别概率逐项累加后求均值，阈值仍为 0.80。
- 分发器保持 `7200128`，启动入口和公共协议不变。

### MCU

- MCU 版本更新为 `7100961 / FP2_MULTI3_REPLAY`。
- FP2 结果等待时间由 3000 ms 调整为 10000 ms，为图片双模型六次推理、数字三次推理、受控复位和监听器重发留出完整预算。
- FP2 菜单文字注明三帧均值；通信协议、控制层、规划算法和比赛行为未改变。

## 下一步实机流程

1. 安全弹出 `H:`，复位或重新上电二号摄像头。
2. 在 Keil 下载 MCU `7100961`。
3. 无线串口执行 `F -> I`，等待 FP2 状态变为 READY。
4. 放好图片后按 `1`，等待 `FP2_RESULT` 和重新 READY；图片识别预计约 2.5 到 3 秒。
5. 放好数字后按 `4`，等待 `FP2_RESULT` 和重新 READY；数字识别预计约 1.3 秒。
6. 若结果置信度低于 0.80，出现 LOW_CONFIDENCE 属于识别结果，不等同于通信失败；真正链路成功的判据是 MCU 收到匹配 session/request/type/slot 的结果且 timeout 不增加。
