# FP2 极简模型 Worker（7200129 / 7200130）

## 实机证据

- 7200127/7200128 修复任务交接后，真实图片请求仍超时。
- 失败后 H 盘中 `fp2_job.bin` 已消失、`fp2_last.bin` 不存在，证明分发器已进入 worker，worker 在结果落盘前退出。
- 数字命令是在图片请求仍处于 `REQUEST_WAIT` 时发送，被 MCU 正确拒绝，因此该轮没有真正测试数字 worker。
- 旧 worker 会同时驻留分发器、worker 和 4.2KB 的 `fp2_common`；该形态与此前“完整协议外壳加入后首轮推理退出”的问题一致。

## 修改

- 图片 worker 更新为 `7200129`，数字 worker 更新为 `7200130`。
- 两个 worker 改为单文件极简运行时，不再导入 `fp2_common`。
- 图片 worker 约 6.1KB，数字 worker 约 5.8KB；分发器在导入 worker 前主动删除读取/校验函数并执行 GC。
- 保留 FP2 20 字节协议、UART12、持久会话、共享原始 ID 压缩映射、图片双模型 0.80 融合和数字模型 0.80 阈值。
- 新增 `/sd/fp2_trace.bin` 单字节阶段标记。若仍失败，挂载 H 盘即可定位最后阶段，不再靠猜测。

图片阶段：`01`进入、`02`相机就绪、`03`UART就绪、`04`模型1开始、`05`模型1完成、`06`模型2开始、`07`模型2完成、`08`结果落盘。

数字阶段：`21`进入、`22`相机就绪、`23`UART就绪、`24`推理开始、`25`推理完成、`28`结果落盘。

## 当前版本

- MCU：`7100960`，未修改。
- 全局摄像头：`7100428`，未修改。
- 二号摄像头：监听器 `7200127`、分发器 `7200128`、图片 worker `7200129`、数字 worker `7200130`。
- 设备文件已同步并逐项哈希核对，旧任务和旧阶段标记均已清除。

## 测试

安全弹出 H 盘并复位后，执行 `F -> I -> READY -> 1`。必须等图片请求完成、监听器恢复 `READY` 后，才能按 `4` 测数字，不能在 `REQUEST_WAIT` 时连续发送。

## 第二次实机现场

- 图片与数字请求仍超时；两次均能在超时后恢复监听器，协议错误仍为 0。
- H 盘中任务文件已被消费，但结果文件和最早阶段标记 `fp2_trace.bin` 都不存在。
- 这说明 worker 已取得任务，但进入后连第一笔 `/sd` 阶段记录都无法持久化，不是卡在模型1或模型2。
- 检查时 Windows 已再次自动挂载 `H:`。最符合证据的原因是 worker 触发复位后 USB 大容量存储重新枚举并被 Windows 占用，OpenART 随即失去 `/sd`，因而无法读取模型、写阶段或写结果。
- 下一轮不再修改程序：安全弹出 H 后断开二号摄像头与电脑的 USB 数据连接，改由赛车独立供电，再从 MCU 无线串口执行真实识别。这也与比赛环境一致。
