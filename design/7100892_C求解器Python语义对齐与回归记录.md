## 7100891故障根因

1. `micro_scheduler.c`和`push_bfs.c`的最小堆弹出操作使用旧根节点参与比较，未用末节点正确下沉，搜索顺序可能错误。
2. 已经到达目标并按游戏规则消失的箱子，在C调度和Action生成中仍被当作永久障碍。
3. 微任务调度只检查车辆能否到达箱后，没有检查箱子的整段推进通道是否被另一个未完成箱子占据。
4. 旧回退排列只产生4个不同顺序，未覆盖3个箱子的全部6种顺序；代价统计也错误使用最终车辆位置。
5. 求解器没有在报告成功前对最终Action做逐格物理语义回放。

故障图为Python项目`maps_import/map2.txt`，实车起点`(2,7)`。7100891会先把box2推到`(10,6)`，随后又试图把box1推入同一格，执行层因此正确报`PUSH_MAP_MISMATCH`。

- 新增最终Action语义校验：四邻域、逐格、车辆不穿墙/箱、箱子不撞墙/箱、目标消失语义、最终箱子和目标全部清空。

### 日志中的上游车位跳变

290条`RUN_TELEM`中有18次相邻250ms帧的位置变化超过0.45格。Action 7/8附近最明显：车辆已经停车时，视觉位置在约`(11.1,5.9)`与`(10.1,5.6)`之间整格切换，视觉角度同时在约78度与23度之间切换。编码器和控制状态不支持车辆在250ms内发生这种位移，因此判定为上位机/显示链路/全局视觉产生的错误车位帧，而不是车辆真实跳动。

当前`HOLD -> VIS_DRAIN -> VIS_STABLE_6`最终选回了正确位置簇，所以本次仍完整完成；但如果错误簇连续稳定，现有状态机仍有误采风险。

后续精度优化优先级：

1. 单格运动以标定后的200mm编码器里程为主体；视觉只允许提供有界的小修正，例如纵横位置修正限制在几十毫米、方向修正限制在十几度。超出范围的视觉簇直接忽略，禁止把单格目标距离改成80至300mm不等的大范围数值。
2. 全程锁定任务开始时的地图航向，并用IMU短时增量传播；运动中不使用跳变的实时视觉角度改变车体方向换算。
3. 视觉只在格间停车后作为多帧确认和小范围校正，必须同时通过“接近期望格”和“接近编码器预测位置”两道门限。
4. 错误视觉帧只降低视觉置信度，不覆盖逻辑格坐标；逻辑格始终由Action的`from/to`和成功提交状态维护。
