# FP2 软复位交接修复

## 现场结论

- MCU `7100962` 已成功初始化会话，并对图片、数字请求各重发 8 次。
- 失败现场保留了合法的 `fp2_job.bin`，内容为 session=1、request=2、数字识别、slot=0。
- `fp2_trace.bin` 和 `fp2_last.bin` 均不存在。
- Worker 入口会立即删除 job 并写 trace，因此该现场证明 Worker 从未进入；问题位于监听器写入任务后的复位交接，不在模型加载或三帧推理。

## 修改

- 监听器更新为 `7200136`，任务落盘后优先调用 `machine.soft_reset()`，显式清空 Python 堆并重新执行 boot/main 分发流程。
- 原 `machine.reset()` 保留为第二级兜底；若两种复位均异常返回，再启动 1 秒硬件看门狗。
- 监听器在交接前写阶段码：图片 `0xA1`，数字 `0xA2`。Worker 启动后会立即覆盖为自身入口阶段码。
- 图片 Worker 更新为 `7200137`，数字 Worker 更新为 `7200138`；完成结果后同样使用软复位优先的返回路径。
- 图片双模型融合、数字单模型、0.80 阈值、三帧类别概率均值、会话紧凑 ID 映射和 FP2 协议均未改变。

## 部署与验证

- 修改前源码及现场文件备份：`design/_codex_backups/20260723_BEFORE_FP2_SOFT_RESET_HANDOFF`。
- 已同步 `H:`，监听器、两个 Worker、main 分发器均与电脑源码 SHA-256 一致。
- 已清除旧 `fp2_job.bin`、`fp2_last.bin`、`fp2_trace.bin` 和 `fp2_state.bin`。
