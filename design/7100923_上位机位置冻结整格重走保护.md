# 7100923 上位机位置冻结整格重走保护

## 问题证据

- 实车日志：`C:\Users\L\.codex\attachments\dc7c91f2-47c7-4f25-b85e-87f6d9c2e0e7\pasted-text.txt`
- 固件：`7100922 / ADAPTIVE_VIS_ALIGN_RECOVERY`
- 故障步骤：`S021 FREE A12.03 (10,10)->(11,10)`，上下文为`BOX_NEAR_PRECISE`、`strict=1`。
- 上位机位置持续为`car=(10.1,10.0)`，但位置包计数持续增加且`age`保持在约`5..275ms`，因此不是串口断联，而是“新位置帧重复同一冻结坐标”。
- 每轮编码器运动已完成约一格后，视觉仍稳定落在出发格。旧逻辑把它解释为“还没走”，重新启动完整200mm运动；`rebase`从3增加到4、5，现实车辆因此持续向前。

## 根因

`action_follower_poll()`在6帧位置复核后，如果视觉仍位于`from_x/from_y`且当前不是`interaction_locked`，会清零对齐次数并重新进入`WAIT_ORIGIN`，随后再次执行整格运动。该路径不是短距离ALIGN，不受`FOLLOWER_ALIGN_MAX_ATTEMPTS`限制，因此冻结坐标可触发无限整格重走。

## 7100923修复

1. 删除“视觉仍在出发格就重新跑完整一格”的行为。
2. 编码器运动已经完成而视觉仍在出发格时，保持电机锁定，再等待一组6帧稳定视觉，让正常延迟有机会追上。
3. 额外6帧内视觉到达目标格时，沿原有精确验收/对齐流程继续。
4. 额外6帧后仍稳定停在出发格时，进入`ACTION_FOLLOWER_REPLAN / GRID_MISMATCH`，由任务层锁车并进入`PAUSED_REPLAN`；绝不再次驱动车辆。
5. `RUN_VIS`新增`from_wait=current/limit`，正常通常为`0/1`；冻结保护触发后为`1/1`。
