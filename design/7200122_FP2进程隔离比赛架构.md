# FP2 进程隔离比赛架构（7200122-7200125）

## 根因

- 7200120在CMM和UART12开启时连续完成双模型推理，证明硬件、模型、串口和模型释放正常。
- 7200121约18.6KB的“协议+推理单进程”仍在首次自动推理时使设备掉线。
- 根因是OpenART原生推理需要连续工作区，协议状态机与TensorFlow同时驻留会越过临界点；普通`gc.mem_free()`不能完整反映该工作区。

## 架构

- `main.py` / `fp2_boot_dispatcher.py`：启动分发器，约0.6KB，识别任务文件类型。
- `fp2_listener.py`：FP2监听器，识别数7200122；不导入sensor/tf，负责探活、会话、请求、伪识别、重发和落盘真实任务。
- `fp2_image_worker.py`：图片工作程序，识别数7200123；只加载公共协议和两个图片模型，执行0.80阈值融合并回传。
- `fp2_digit_worker.py`：数字工作程序，识别数7200124；只加载公共协议和数字模型，0.80阈值。
- `fp2_common.py`：20字节FP2帧、UART12/CMM、任务/状态/最后结果文件和最多3组真实ID压缩映射。
- 启动分发器源码识别入口记为7200125，但正常串口探活显示监听器7200122；识别结果帧分别显示7200123或7200124。

真实请求流程：监听器校验请求 -> 保存20字节任务 -> `machine.reset()` -> 分发器只加载对应工作程序 -> 工作程序删除任务防重启循环 -> 相机稳定500ms -> 推理 -> 更新ID映射/最后结果 -> UART回传 -> 250ms后复位回监听器。

## 配置

- `fp2_listener.py`中的`FAKE_RECOGNITION_ENABLE=True`仍按用户先前要求默认开启。
- 真实联调时只改为False；工作程序无需修改。
- ROI `(55,40,245,180)`；图片/数字阈值0.80；UART12对应MCU UART1 B12/B13。

## MCU 7100960

- `APP_FP2_RESULT_TIMEOUT_MS`由2000ms放宽到6000ms，覆盖复位、500ms稳定、双模型约1.45s和回传。
- `APP_MCU_STAGE_NAME=FP2_PROCESS_ISOLATED`。
- 未修改运动、路径算法、全局视觉或电机控制。
- Keil全量构建：0错误、0警告；Code=259784，RO=35376，RW=684，ZI=632768。
