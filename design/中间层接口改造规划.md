# 中间层接口改造规划

## 目标

在当前 RT1064 控制代码中，开放算法层输出协议接口，使小车能消费算法规划器产出的结构化 Action 序列，逐条自动执行推箱子任务。

## 四、位姿融合策略

### 问题

- OpenART 视觉位姿：低频（~10-30Hz），但绝对准确（无漂移）
- IMU 航向 + 编码器增量：高频（200Hz），但会漂移

### 方案

```
视觉帧到达时 (10-30Hz):
    更新参考位姿:
        x_ref = x_vision
        y_ref = y_vision
        theta_ref = theta_vision
    重置里程计增量累加器

每次 5ms 控制周期:
    用 IMU + 编码器更新局部位移（已有 odometry_update）:
        x_local += odom_world_dx
        y_local += odom_world_dy
        theta_local = imu963ra_yaw_angle（相对参考帧的增量）
    
    融合位姿（中间层位置闭环用）:
        x_current = x_ref + x_local
        y_current = y_ref + y_local
        theta_current = theta_ref + theta_local  // 或直接用 imu963ra_yaw_angle
    
    位置闭环 P 控制:
        dx = target_x - x_current
        dy = target_y - y_current
        vx = clamp(KP_POS * dx, -MAX_V, MAX_V)
        vy = clamp(KP_POS * dy, -MAX_V, MAX_V)
    
    航向闭环（复用已有）:
        omega = imu963ra_yaw_hold_calculate()  // 或指定 theta_target
```

**关键**：视觉位姿来自竞赛系统 → 屏幕 → OpenART，不是里程计的积分。IMU/编码器只负责填补视觉帧间的 100ms 空白，提供平滑的速度估计。

## 五、Action 数据结构（C 语言定义）

```c
// ============================================================
// 算法层输出接口数据结构
// ============================================================

// 推动方向编码
#define PUSH_UP    0
#define PUSH_DOWN  1
#define PUSH_LEFT  2
#define PUSH_RIGHT 3

// 推动元数据（push_box / push_bomb 共用）
typedef struct {
    uint8  object_id;          // 箱子或炸弹编号
    uint8  obj_start_x;        // 物体起始网格坐标
    uint8  obj_start_y;
    uint8  obj_target_x;       // 物体目标网格坐标
    uint8  obj_target_y;
    uint8  push_dir;           // 推动方向: PUSH_UP/DOWN/LEFT/RIGHT
} push_meta_t;

// 单条路径点
typedef struct {
    float x;                   // 世界坐标 X (mm)
    float y;                   // 世界坐标 Y (mm)
} waypoint_t;

// Action 类型
#define ACTION_FREE_MOVE  0
#define ACTION_PUSH_BOX   1
#define ACTION_PUSH_BOMB  2
#define ACTION_WAIT       3

// 单条 Action
typedef struct {
    uint8  type;               // ACTION_FREE_MOVE / PUSH_BOX / PUSH_BOMB / WAIT
    
    // 公共字段
    uint8  target_x;           // 目标网格坐标（WAIT 时无效）
    uint8  target_y;
    float  theta;              // 目标朝向（弧度），NAN 表示不控制朝向
    
    // waypoints（阶段一为 null，阶段二填充路径点）
    waypoint_t *waypoints;     // 指向路径点数组的指针
    uint8  wp_count;           // 路径点数量
    
    // 推动元数据（仅 PUSH_BOX / PUSH_BOMB 有效）
    push_meta_t *push_meta;    // 指向推动参数的指针
    
    // WAIT 参数
    float  wait_duration;      // 等待时长（秒）
    
    // 窄通道标记（阶段三使用）
    uint8  narrow_passage;     // 0 = 正常, 1 = 窄通道（降速50%）
} action_t;

// 算法层输出
#define MAX_ACTIONS 64

typedef struct {
    action_t actions[MAX_ACTIONS];
    uint8   count;              // Action 总数
    uint8   success;            // 算法是否求解成功
} solver_output_t;
```

## 六、中间层状态机

```
                    ┌─────────┐
         加载Action │  IDLE   │
              ────→ │         │ ────→ DONE (队列空)
                    └────┬────┘
                         │ 进入第一条 Action
                         ▼
              ┌──────────────────────┐
              │   根据 type 分发      │
              └──┬───────┬───────┬───┘
                 │       │       │
        free_move│  push │  wait │
                 ▼       ▼       ▼
           ┌────────┐ ┌──────────┐ ┌─────────┐
           │ MOVING │ │ PUSHING  │ │ WAITING │
           │        │ │          │ │         │
           │ 逐waypoint│├─APPROACH│ │ 倒计时  │
           │ 导航    │ │  (走到   │ │ 到期→   │
           │        │ │  推箱站位)│ │ _advance│
           │ 最后点 │ │→PUSH    │ └─────────┘
           │ 到达→  │ │  (匀速推)│
           │_advance│ │ 箱到目标│
           └────────┘ │ →_advance│
                      └──────────┘
                           │
              _advance()   ▼
              ┌──────────────────────┐
              │  idx++, elapsed=0    │
              │  idx>=count → DONE   │
              │  否则 _enter_action  │
              └──────────────────────┘

    异常路径:
      任一状态 30s 超时 → STUCK（上报错误，请求重规划）
      任一状态收到视觉层"偏差过大"信号 → RECOVERING（阶段三）
```

### 各状态的核心逻辑

**MOVING (free_move)**：
```
每5ms:
  1. 检查是否到达当前 waypoint
     dist(car_x, car_y, wp[cur].x, wp[cur].y) < WP_ARRIVE_MM
     → wp_i++
  2. wp_i >= wp_count → _advance()
  3. 位置P控制:
     dx = wp[cur].x - car_x_mm
     dy = wp[cur].y - car_y_mm
     vx = clamp(KP_POS * dx, -MAX_V, MAX_V)
     vy = clamp(KP_POS * dy, -MAX_V, MAX_V)
  4. 航向: theta_target != NAN → _steer_angle(), 否则 omega = 0
  5. 输出 (vx, vy, omega) 给控制层
```

**PUSHING (push_box/push_bomb)**：
```
APPROACH 阶段:
  1. 目标 = push_position（物体反方向一格的世界坐标）
  2. 同 MOVING 逻辑，P 控制走到 push_position
  3. dist < ARRIVE_MM → 切换到 PUSH 阶段

PUSH 阶段:
  1. 沿 push_dir 输出恒定速度 vx=±PUSH_V 或 vy=±PUSH_V
  2. 监控物体是否到达目标格（来自视觉层的位置数据）
     object_grid == target_grid → _advance()
  3. 监控箱子速度（阶段三）:
     box_speed < 5px/s 持续 1.0s → 卡住 → 触发纠错
```

**WAITING**：
```
每5ms:
  wait_timer += 0.005
  wait_timer >= duration → _advance()
  输出 (0, 0, 0)
```

## 八、控制层接口改造

### 当前接口（车体坐标系）

```c
// 当前使用方式
float target_angle = 90.0f;        // 车体坐标系运动方向（度）
float target_linear_speed = 100.0f;// 速度（编码器脉冲/5ms）
motion_set_velocity(target_angle, target_linear_speed);

// 在 motor_control_5ms() 中
k_calculate(move_angle, move_speed, rotate_speed, wheel_target_speed);
```

### 新增接口（世界坐标系）

```c
// 新增：世界坐标系速度接口
// vx, vy: 世界坐标系 X/Y 速度 (mm/s)
// omega:  旋转角速度 (°/s)
void motion_set_world_velocity(float vx, float vy, float omega);
```

**实现细节**：

```c
void motion_set_world_velocity(float vx, float vy, float omega)
{
    float body_vx, body_vy, body_speed;

    // 1. 世界→车体坐标旋转（用当前IMU航向）
    float yaw_rad = -imu963ra_yaw_angle * PI / 180.0f;
    body_vx =  vx * cosf(yaw_rad) - vy * sinf(yaw_rad);
    body_vy =  vx * sinf(yaw_rad) + vy * cosf(yaw_rad);

    // 2. 车体速度 → angle + speed（内部单位：脉冲/5ms）
    body_speed = sqrtf(body_vx*body_vx + body_vy*body_vy);
    target_linear_speed = body_speed * MM_S_TO_PULSE_PER_5MS;
    target_angle = atan2f(body_vy, body_vx) * 180.0f / PI;

    // 3. omega → rotate_speed（内部单位：脉冲/5ms）
    target_rotate_speed = omega * DEG_S_TO_ROTATE_PULSE;

    // 4. 标记自动模式，motor_control_5ms() 内据此切换 rotate_speed 来源
    auto_control_mode = 1;
}
```

**新增全局变量**：

```c
float target_rotate_speed = 0.0f;  // 中间层设定的旋转分量（脉冲/5ms）
uint8 auto_control_mode = 0;       // 0=手动(航向保持PD), 1=自动(中间层给定omega)
```

**motor_control_5ms() 内唯一改动**：

```c
// 原来: rotate_speed = imu963ra_yaw_hold_calculate();
// 改为:
if(auto_control_mode)
    rotate_speed = target_rotate_speed;       // 中间层给定
else
    rotate_speed = imu963ra_yaw_hold_calculate(); // 手动航向保持
```

**单位转换常量（需上机标定）**：

```c
// 世界速度 mm/s → 内部脉冲/5ms
// ODOM_PULSE_TO_MM = PI * 65.0 / 2048.0 * ODOMETRY_QUICK_SCALE
#define MM_S_TO_PULSE_PER_5MS   (0.005f / ODOM_PULSE_TO_MM)

// omega °/s → rotate_speed 脉冲/5ms
// 基于车中心到轮距离 WHEEL_BASE_RADIUS_MM ≈ 100mm（需实测标定）
#define WHEEL_BASE_RADIUS_MM    (100.0f)
#define DEG_S_TO_ROTATE_PULSE   ((PI/180.0f)*WHEEL_BASE_RADIUS_MM*0.005f/ODOM_PULSE_TO_MM)
```

### 保持兼容性

- 蓝牙手动模式：继续用 `motion_set_velocity()`，内部设 `auto_control_mode=0`
- 自动模式（中间层驱动）：用 `motion_set_world_velocity()`，内部设 `auto_control_mode=1`
- `motor_control_5ms()` 内通过 `auto_control_mode` 切换 `rotate_speed` 来源

## 九、视觉数据接口（来自 OpenART）

需要新增一个串口协议解析模块，接收 OpenART 发来的结构化数据：

```c
// OpenART → MCU 串口数据包（示意，具体协议需和视觉组对齐）
typedef struct {
    uint8  frame_id;            // 帧序号
    int16  car_x_mm;            // 车世界坐标 X (mm)
    int16  car_y_mm;            // 车世界坐标 Y (mm)
    int16  car_theta_deg;       // 车头朝向（度 × 10，即 0.1° 分辨率）
    uint8  box_count;           // 箱子数量
    int16  boxes[3][2];         // 各箱子网格坐标 [(x,y), ...]，-1 表示已完成
    uint8  bomb_count;          // 炸弹数量
    int16  bombs[2][2];         // 各炸弹网格坐标
    uint8  walls_changed;       // 墙体是否有变化（被炸）
    uint8  checksum;            // 校验和
} vision_packet_t;
```

此模块独立于中间层，仅负责：
1. 接收串口数据，验证校验和
2. 更新全局视觉状态 `vision_state_t g_vision`
3. 触发"视觉新帧到达"标志位

## 十二、实施顺序建议

### 阶段一：搭骨架（最小可行链路）

1. **定义数据结构**：`action_protocol.h` — action_t, push_meta_t, waypoint_t
2. **实现 world→body 坐标旋转**：`motion_control.c` 新增 `motion_set_world_velocity()`
3. **实现最简 free_move**：状态机只需 IDLE → MOVING → DONE，无 waypoints 时直线走到 target
4. **视觉模拟注入**：先用蓝牙命令手动注入"车在 (x,y)" 的假数据，验证位置闭环
5. **联调**：蓝牙发一个模拟 Action → 车自动走到目标格

### 阶段二：完善功能

6. **waypoint 导航**：支持多点路径，逐点切换
7. **push_box/push_bomb**：APPROACH + PUSH 两阶段
8. **wait**：计时等待
9. **位姿融合**：IMU/编码器帧间插值
10. **超时/卡住检测**：STUCK 状态 + 错误上报

### 阶段三：性能优化 + 算法移植

11. **移植 Python 算法层**：`solve()` 函数 C 化
12. **视觉串口真实对接**：替换模拟注入
13. **窄通道降速**
14. **偏差检测 + 重规划**
15. **全图批量测试**：24 张地图回归
