# 7100947 统一可恢复门控策略

## 1. 主线与根因

本轮属于完整三图比赛主线的阻塞修复。7100946 实车已正常完成约 350 mm 出基地和 FULL_MAP 加载，但任务反复进入 `MISSION_ARMING -> MISSION_RETRY_WAIT`，最终未执行第一步。

根因不是电机、求解器或串口：出基地后全局视觉持续给出约 `(0.1,0.2)` 的车位，该位置落在边界墙格。`vision_world` 为了让求解器工作，把车格吸附到最近空格；任务启动层又正确地拒绝“实时车格与规划起点不一致”，两个策略组合后形成永久重试。旧版同时只等 4 个位置包，而点测稳定判据需要 6 帧/200 ms；`action_follower` 还重复执行了一层视觉航向稳定门控。

修改前备份：`project/_codex_backups/pre_7100947_GATE_POLICY_20260721_163500`。

## 2. 门控分级

统一为四类，不再把所有异常都处理成停车并解除任务：

1. `短暂外部数据异常`：全局视觉离线、位置无效、不稳定、地图未更新、规划输入变化。电机锁定，任务保留，显示明确 gate，继续请求数据；稳定 6 帧且不少于 200 ms 后自动恢复。
2. `可恢复运行异常`：起点变化、计划过期、跟随器要求重规划、推后地图超时/不一致。停车，请求新版 FULL_MAP，重新解算并武装；启动与运行重规划分别记录，诊断上限显示为 6 次。
3. `任务语义失败`：识别会话失败、N2 第二阶段失败、地图结构无法求解等。停止当前任务，进入完赛复核和返航，不允许车辆带着错误计划继续推物。
4. `真实硬故障`：用户急停、基地主动退出命令无法启动/运动故障、持续无返航路径、返航运动多次真实失败。只有这些条件进入 `MATCH_STATE_FAULT`。

## 3. 关键实现

- 新增 gate：`PREFLIGHT / WAIT_MAP / WAIT_POSE / WAIT_POS_STABLE / WAIT_HEADING_STABLE / REFRESH_PLAN / RUNTIME_REPLAN / FINISH_SCAN / RETURN_POSE`。
- `MATCH` 与 `MATCH_GATE` 遥测输出 gate、等待轮数、恢复原因、规划原始车位、规划车格及 `adjusted` 标志。
- 规划起点发生吸附时，原始位置到吸附格任一轴超过 0.4 格（80 mm）即禁止启动，进入 `START_POSE_CHANGED -> WAIT_MAP -> REFRESH_PLAN`；不再从远距离假起点出发。
- 任务启动稳定条件统一为 6 个新位置包且至少 200 ms，删除 follower 内重复的视觉航向门控；mission 层仍保留 6 帧中值航向采样并交给 IMU 锁航向。
- `POSE_INVALID / START_POSE_CHANGED / PLAN_STALE / BAD_STATE / REPLAN_REQUIRED / FOLLOWER_FAULT / PUSH_MAP_TIMEOUT / PUSH_MAP_MISMATCH` 统一走恢复路径。
- 返航短时无位置或无航向只进入 `RETURN_POSE`，每 3 秒重新请求 FULL_MAP；直线返航启动失败自动降级为地图 BFS 返航，不再立即锁死。
- 完赛复核拿不到地图时仍允许返航；地图等待超时只增加等待轮数并重发请求。

完整断电、下载并重新上电后执行：

`F -> S -> B -> 6 -> 1 -> C -> F/L/R -> P -> Q -> S -> A -> S -> V -> Y`

- `F -> S -> B`：确认第二摄像头在线后返回。
- `6 -> 1`：进入完整比赛菜单并选择单图 SAFE 验证。

- `S -> A -> S`：确认配置、武装，再确认状态为 ARMED。
- `V -> Y`：执行预检并二次确认启动。

验收重点不是要求视觉永不抖动，而是：出基地后不得直接 `FAULT/MISSION_ARM`；短时异常应看到具体 `gate` 并自动恢复。若持续显示 `plan_pose_raw` 接近边界且 `adjusted=1`，说明全局视觉仍把车放在墙格，程序会拒绝假起点；此时保留完整串口日志用于修正视觉/基地出发距离，而不是继续修改电机控制。
