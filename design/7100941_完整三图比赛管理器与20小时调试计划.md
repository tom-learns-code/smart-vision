## 1. 本轮目标与边界

本轮不是继续修改单个PID或单步跟随，而是在已验证单图完赛链路外增加一层完整比赛管理器。目标是让MCU能够从左侧基地出发，等待地图加载，选择算法，完成一张图，复核完成状态，回到基地，再重复到三张图结束；同时保留串口单图调试、第二摄像头诊断和已有控制层验证入口。

必须保持的稳定底线：

1. `7100938`仍是实车确认可完赛的强制回退版本，本轮候选不能覆盖该检查点。
2. 电机/编码器物理映射、方向符号、PID、CPR4096、里程比例0.915、IMU锁航向、旋转参数及制动提前量不改。
3. 箱子、炸弹及目标点八邻域的严格定位、PUSH延迟视觉屏障、PUSH后禁止主动追加ALIGN、错误格拒绝继续保留。
4. 全局摄像头和第二摄像头代码本轮均不改。
5. 新完整比赛流程必须两步启动：先ARM但锁车，再单独确认START才允许运动。

## 2. 当前三端识别信息

- MCU：`7100941 / MATCH_MANAGER_UART_FULL3`，`CONTROL_DEBUG_ENABLE=0U`。
- 无线调试串口：UART8，115200，TX=`D16`，RX=`D17`，中断接收和非阻塞发送队列。
- 全局摄像头：`oa_id=7100425`，负责全图、车位置和角度，接MCU现有视觉串口。
- 第二摄像头：`fp_id=7200102`，MCU UART1 `B12/B13`，摄像头UART12，当前`FAKE_RECOGNITION_ENABLE=True`。

## 3. 软件分层

新增文件：

- `project/code/match_manager.h`
- `project/code/match_manager.c`

职责边界：

- `match_manager`只负责比赛轮次编排，不重写求解器、mission或电机控制。
- `planner_service`负责把当前全图转换成计划。
- `mission_manager`负责一张图内的观察、移动、推箱、推炸弹及动态地图事务。
- `action_follower/point_test/motion_control`继续负责真实运动与闭环。
- `pc_console`负责UART菜单、双确认启动、状态与诊断输出。

主状态机：

`IDLE -> ARMED -> EXIT_PREP -> EXIT_RUNNING -> WAIT_NEW_MAP -> SOLVING -> MISSION_ARMING -> MISSION_RUNNING -> FINISH_MULTI_MAP -> RETURN_PREP -> RETURN_DIRECT/RETURN_PATH -> ROUND_DONE -> BETWEEN_ROUNDS/WAIT_OPERATOR -> 下一轮或 MATCH_COMPLETE`

任何不可恢复错误进入`FAULT`并锁车。`X`始终执行紧急停车；`Q`取消完整比赛并回到未武装状态。

## 4. 完整比赛行为

### 4.1 开局离开左侧基地

基地配置默认为目标`(1,6)`，备用车道`(1,7)`。开局地图尚未出现，因此先用编码器200mm主体位移和IMU锁航向离开基地，默认速度120、方向索引0、距离200mm。方向和距离可以在串口配置菜单中修改。

只有离开基地动作完成后，MCU才记录旧地图版本并请求一帧新`FULL_MAP`。地图必须满足16x12、版本递增、元素数量合法且至少包含箱子/目标/炸弹之一，才能进入求解。

### 4.2 算法模式

提供四种标签策略：

- `AUTO`：当前降级策略。含炸弹时使用N2，否则使用CLASSIC；尚不能可靠判断“有图箱图但无炸弹”的地图。
- `FORCE_UNLABELED`：强制CLASSIC。
- `FORCE_LABELED`：强制N2图像观察算法。
- `ROUND1_CLASSIC_ROUND2_3_N2`：默认。按当前比赛顺序假设，第1张纯箱图，第2、3张带图识别。

注意：默认轮次顺序是待赛制实测确认的明确假设，不是从地图自动识别出来的事实。第二摄像头未来加入“无图片/无数字”类别后，再启用真正的自动判断。

### 4.3 运行档位

- `SAFE`：每次只执行一格，稳定性最高，当前完整比赛默认档。
- `NORMAL`：只合并开放区域同方向FREE，PUSH仍逐格。
- `FAST`：允许同方向FREE和连续PUSH合并，使用7100940的推前中心与推后轴向补足候选逻辑。

比赛管理器ARM前可切档；开始运行后锁定配置，防止中途误改。

### 4.4 完成复核

单图mission结束或暂停后，MCU默认连续请求3个新版本`FULL_MAP`。三帧都满足`box=0 && bomb=0`才判定地图已经清空。可在菜单中改为5帧或7帧。

- 三帧全清：允许直接点到点返回左侧基地。
- 任一帧未清：认为任务未完整完成，保留最新地图并规划避障返航。
- 扫描超时：进入`FINISH_SCAN`故障并锁车，不凭旧图猜测完成。

### 4.5 返回基地

返回策略：

- `AUTO`：地图清空时直返；地图仍有元素时BFS规划返航。
- `DIRECT`：始终尝试直返，启动失败直接报错。
- `PLANNED`：始终基于墙、箱、炸弹做四邻域BFS，一格一格强重锚返回。

BFS目标候选为`(1,6)`、`(1,7)`、`(2,6)`、`(2,7)`，旧右侧基地没有进入代码。若车辆已位于这些目标之一，直接结束返航，不构造零长度动作。AUTO直返本轮若启动失败，只临时降级为BFS，不修改后续轮次的用户配置。

### 4.6 三轮切换

- `NEXT_MAP`：返航后等待1秒并再次执行出基地、请求新图。当前与`RETRY_SAME`的MCU动作相同，因为比赛上位机换图机制尚未确认。
- `RETRY_SAME`：保留接口，等待确认重新出基地时上位机是否仍允许选择同一张图。
- `WAIT_OPERATOR`：每轮返航后停在`WAIT_OPERATOR`，串口发送`R`才进入下一轮。首次实车三轮验证必须使用这个策略。

## 5. 串口主菜单

上电后主菜单：

- `1`：请求并打印一帧全图。
- `2`：旧单图规划/Action菜单，电机锁止。
- `3`：旧单图受控执行菜单。
- `4`：打印全局视觉链路状态。
- `5`：打印缓存地图。
- `6`：进入完整比赛菜单。
- `F`：第二摄像头FP2诊断。
- `V`：切换视觉链路详细/安静报告。
- `X`：紧急停车。
- `H`：重印当前菜单。

完整比赛运行期间，旧`1/2/3/F`入口不能抢占比赛管理器；返回主菜单也不会自动取消正在运行的完整比赛。

## 6. 完整比赛菜单

进入方式：主菜单发送`6`。

- `1`：选择单轮完整流程。
- `3`：选择三轮完整比赛。
- `G`：选择保底流程，出基地、加载地图、回基地，共三轮；规则得分语义待确认。
- `P`：循环`SAFE/NORMAL/FAST`。
- `M`：循环`AUTO/UNLABELED/LABELED/ROUND_SEQUENCE`。
- `N`：循环`NEXT_MAP/RETRY_SAME/WAIT_OPERATOR`。
- `A`：ARM。只建立会话，电机保持锁止。
- `Y`：远程启动。只有已ARM且预检通过时才运动。
- `R`：在`WAIT_OPERATOR`状态继续下一轮。
- `S`：打印完整比赛状态。
- `V`：打印预检。`ready=0x03/0x03`才允许Y，bit0为IMU，bit1为全局视觉链路。
- `C`：配置速度、基地、距离、返航与超时。
- `K`：两按键事件UART模拟器。
- `D`：诊断与台架入口。
- `T`：循环`QUIET/EVENT/ACTION/CONTROL/FULL`遥测等级。
- `Q`：取消并解除完整比赛武装。
- `B`：返回主菜单，不取消活动比赛。
- `X`：紧急停车。

每次命令后都会重印当前菜单和可用选项。

## 7. 配置与诊断菜单

### 7.1 配置菜单 `6 -> C`

- `1/2/3`：速度100/120/150 counts per 5ms，同时作用于基地出发和mission。
- `E`：出基地距离200/400/600mm。
- `D`：车体方向0..7，`0前/2右/4后/6左`。
- `B`：首选基地车道y=6/y=7互换。
- `R`：返航AUTO/DIRECT/PLANNED。
- `V`：完赛复核3/5/7帧。
- `W`：地图等待10/15/30秒。
- `P`：打印当前完整状态。
- `Q`：回完整比赛菜单。

### 7.2 双按键占位菜单 `6 -> K`

- `1`：模拟KEY1短按，循环速度档位。
- `2`：模拟KEY1长按，第一次ARM，已ARM时START。
- `3`：模拟KEY1双击，循环标签策略。
- `4`：模拟KEY2短按，循环单轮/三轮/保底。
- `5`：模拟KEY2长按，紧急停车。
- `6`：模拟KEY2双击，循环下一地图策略。

实体GPIO尚未分配。得到两个按键引脚后，只需把短按、长按、双击解析结果调用`match_manager_handle_key()`，不再改比赛状态机。

### 7.3 诊断菜单 `6 -> D`

- `S`：比赛状态、配置、轮次和计数。
- `V`：全局视觉链路和车位。
- `M`：当前单图mission、跟随器、PID状态。
- `P`：规划摘要和plan generation。
- `F`：第二摄像头FP2状态。
- `L`：台架模式，仅跳过一次基地出发；不会复用旧图，Y后仍请求一帧新地图。
- `Y`：启动由L武装的台架流程。
- `I`：故障注入探针；正式构建默认编译关闭。

## 8. 推荐操作流程

### 8.1 首次无运动预检

完整重新上电后：

`6 -> S -> V -> C -> P -> Q -> D -> V -> F -> B -> Q`

此流程不ARM、不发Y，车不应运动。确认MCU识别号7100941、`ready=0x03/0x03`、全局视觉online、FP2按预期在线或离线、默认SAFE、默认ROUND_SEQUENCE和返航AUTO。

### 8.2 单轮完整流程首次验证

从主菜单开始：

`6 -> 1 -> P直到SAFE -> M选择本图真实类型 -> N直到WAIT_OPERATOR -> C -> 设置出基地方向/距离 -> P -> Q -> V -> A -> 再次S确认ARMED -> Y`

Y之后车辆先离开基地，再请求新图、求解、执行、复核、返航。首次测试只跑一轮。正常结束应看到`MATCH_COMPLETE`且`done=1`。

### 8.3 三轮分段确认

`6 -> 3 -> P直到SAFE -> M直到ROUND1_CLASSIC_ROUND2_3_N2 -> N直到WAIT_OPERATOR -> C -> 确认参数 -> Q -> V -> A -> S -> Y -> 第一轮返航后等待WAIT_OPERATOR -> S -> R -> 第二轮返航后S -> R`

此流程先验证三轮状态切换，不让NEXT_MAP自动连续跑。每次R前检查车已回基地、上位机下一图状态正确。

### 8.4 全自动三轮远程启动

只有上一流程通过并确认上位机换图规则后：

`6 -> 3 -> P直到SAFE或NORMAL -> M直到正确标签策略 -> N直到NEXT_MAP -> C -> 核对 -> Q -> V -> A -> S -> Y`

`A`后仍锁车，`Y`才是真正远程启动开关。

### 8.5 保底流程

在规则确认“每图出发再回基地可按300秒计”之后才使用：

`6 -> G -> P直到SAFE -> N直到WAIT_OPERATOR或NEXT_MAP -> V -> A -> S -> Y`

当前保底实现会出基地、等地图、跳过求解与任务、返航并重复三轮。规则未确认前不能把它当作正式得分保证。

## 11. 20小时利益最大化调试计划

### MAIN-01 0.5小时：固件与无运动预检

下载7100941，确认菜单、识别号、预检、全局视觉与FP2。失败只处理串口/固件/链路，不动控制参数。

### MAIN-02 1.5小时：基地出发与地图加载

用单轮SAFE、WAIT_OPERATOR。批量试200/400mm和必要方向，目标是一次确定“离开基地后稳定得到新地图”的参数。完成条件：连续3次出发均在超时内得到合法新版本地图。

### MAIN-03 2小时：单轮完整闭环

先纯箱图SAFE跑完，验证求解、mission、3帧复核和返航。若mission内部异常，优先回退7100938确认硬件，再决定是否修本轮编排。

### MAIN-04 2小时：两类返航

一次地图正常清空，验证DIRECT；一次人为保留箱子或使用规划失败图，验证BFS。完成条件：两类都能回到左基地，错误路径不穿墙/箱/炸弹。

### MAIN-05 2小时：三轮状态切换

使用WAIT_OPERATOR，一次跑完三轮框架；每轮之间人工确认上位机状态再R。重点是轮次、地图版本、solver模式、FP2 session是否彻底重置。

### MAIN-06 3小时：三种正式地图类型

纯箱图强制CLASSIC；带图箱图强制N2；带炸弹图强制N2。先使用FP2伪识别验证流程，再换真实模型。每类至少一张完整闭环，不追求速度。

### MAIN-07 2小时：上位机换图与重试规则

实测NEXT_MAP、任务失败返回后能否重选同图、是否自动换图。确认后只需收紧策略接口，不重写状态机。

### MAIN-08 2小时：NORMAL档提速

与SAFE在同图对照总耗时、异常次数和PUSH精度。只接受“FREE合并明显提速且物体邻域稳定不下降”。FAST连续PUSH不作为正式默认。

### MAIN-09 1.5小时：实体按键

拿到GPIO后接入去抖、短按、长按、双击。先只用按键选择和ARM，通过串口观察事件；最后才允许按键START。

### MAIN-10 1小时：保底策略验证

规则确认后，验证出发/回基地三次。若规则不成立，编译关闭该入口，不占用更多时间。

### MAIN-11 2.5小时：完整比赛彩排与冻结

至少两次完整三图彩排。第一次SAFE，第二次NORMAL。记录总时间、每轮结果、返航类型、故障和地图切换。选择最终正式固件并冻结SHA256。

## 22. 正式比赛链路门控审计结论（仅分析）

主线确认存在两个无总超时的动作跟随器状态：`WAIT_VIS_ORIGIN`与`WAIT_VIS_STABLE`。前者在视觉不稳、盲走额度耗尽，或视觉沿程位置不符合段长时可永久等待；后者在视觉在线但坐标离谱、稳定标志不推进时可永久等待。任务开局矫正、观察矫正、普通动作和路径返航均复用该跟随器，因此都继承风险。
