# 7100962 FP2 同请求重试与持久结果取回

## 现场判定

- MCU `7100961` 的会话初始化正常，二号摄像头监听器为 `7200131`，链路在线。
- 图片和数字请求均在 10 秒后超时；等待期间 `rx` 各增加约 5，而 `proto`、`match`、`stale`、`crc`、`fmt` 均未增加。
- 这 5 个接收包与监听器 2 秒一次的探活完全吻合，说明 MCU 没有收到任何结果协议帧。继续扩大超时没有意义。
- 单次请求和复位后的短窗口结果重发都可能丢失；监听器已有“重复请求命中持久结果”的能力，但旧 MCU 只发送一次请求，未利用该恢复路径。

## 修改

- MCU 更新为 `7100962 / FP2_REQUEST_RETRY`。
- `REQUEST_WAIT` 中每 1000 ms 使用相同的 session、request ID、object type 和 slot 重发一次，最多 8 次；总超时仍为 10000 ms。
- 首次请求丢失时，监听器会在下一次重发时启动 worker；worker 忙时重发自然丢弃；worker 返回监听器后，重复请求会直接读取并发送已经落盘的 `fp2_last.bin`，不会重复推理。
- `FP2_STATUS` 新增 `retry=`，同时 `tx` 应随重发递增，便于直接观察恢复链路。
- 配置集中在 `app_config.h`：`APP_FP2_REQUEST_RETRY_MS=1000`、`APP_FP2_REQUEST_MAX_RETRIES=8`、`APP_FP2_RESULT_TIMEOUT_MS=10000`。
