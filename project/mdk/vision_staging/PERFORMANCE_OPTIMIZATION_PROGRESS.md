# OpenART视觉性能优化进度

> 原则：逐项优化、逐项测量；不因单项优化派生需求偏离主路线。  
> 质量包括准确度、灵敏度、连续性和响应延迟。

## 固定路线

1. 分段耗时和全图回退次数统计。
2. 调整车辆丢失后的全图回退调度。
3. 预计算动态采样点屏幕坐标。
4. 单遍提取多类别连通分量。
5. 复用分类、访问和组件缓冲。
6. 拆分车辆与动态对象独立ROI。
7. 评估底层 `find_blobs()` 候选搜索。
8. 最后才评估降低采样密度或简化分类。

## 约束

- 每次只实施一项主要优化。
- 每项都保留开关或清晰回退点。
- 每项完成后记录平均FPS、最低FPS、各阶段耗时和回退次数。
- 无损优化必须保持原采样位置、颜色阈值、组件连接规则和最小像素阈值。
- ROI或候选算法必须验证快速运动、暗区、边缘和部分遮挡下的召回率。

### 6.1 按动态物体距离选择快速搜索半径

- 状态：正常帧性能验证通过，但快速位移触发了连续全图回退，继续补充分级恢复。
- 新增 `USE_ADAPTIVE_FAST_RADIUS` 开关；关闭后完全恢复原固定 `4.0` 格半径。
- 首帧尚未建立物体轨迹时仍使用原 `4.0` 格半径。
- 无未移除物体靠近时使用车辆专用 `2.5` 格半径。
- 任一未移除物体进入 `5.0` 格唤醒距离时，提前恢复原 `4.0` 格物体准备半径。
- 该步骤仅减少无需检查物体时的采样面积，不降低区域内采样密度或分类精度。
- 空地图中央区域：
  - 约 `8.1 FPS`，此前约 `3.7～4.0 FPS`。
  - `region ≈ 82～84 ms`，此前约 `207～214 ms`。
  - `components ≈ 4～5 ms`。
- 移动至裁剪区域时约 `9.3～11.0 FPS`。
- 快速位移期间连续三秒出现每秒2次全图回退：
  - `fallback ≈ 483～506 ms`。
  - 窗口FPS降至约 `1.7～1.8`。
- 结论：小ROI的正常帧收益成立，但必须先消除快速位移时直接全图回退的尖峰，才能判定本阶段完成。

### 6.3 基于车辆速度的预测ROI恢复

  - 在预测中心执行一次 `2.5` 格ROI搜索。
  - 预测搜索失败后仍立即执行全图回退。
- 速度低于阈值时跳过预测，直接全图，避免重复扫描几乎相同的区域。
- 性能输出更新为：
  - `prediction_count`：实际执行预测ROI搜索的次数。
  - `full_fallback_count`：预测失败或没有有效速度后执行全图回退的次数。
- 首版实测：
  - 两次预测ROI均继续触发全图回退。

    形成“漏检 -> 慢帧 -> 更大跨帧位移 -> 再漏检”的反馈链。
- 用户确认上位机车辆始终线性移动，不存在瞬间跳跃；跨帧大位移来自低帧率采样。
- 修正后：
  - 车辆速度改为按真实毫秒计算，单位为 `格/ms`。
  - 未观测到车辆时保留最后可信速度和最后观测时间，不再清零。
  - 预测距离使用距最后观测的真实时间，并乘 `1.15` 时间补偿。
  - 最长预测时间限制为 `1500 ms`，防止长期失联后无限外推。
  - 速度低于 `0.0008格/ms` 时跳过预测，避免静止噪声导致无效搜索。
- 时间预测复测：
  - 约 `13` 次预测ROI中有 `1` 次未继续触发全图回退，成功率约 `8%`。
  - 预测本身已有召回案例，但不足以单独阻止连续回退。
  - 失联阶段全图扫描仍连续发生，单次约 `480～536 ms`，
    最低窗口约 `1.6～1.7 FPS`。

### 2.1 连续失联时的全图回退限频

- 状态：已完成，空地图连续移动实机验证通过。
- 每次新的车辆失联事件仍立即允许一次全图回退。
- 若全图回退未恢复车辆：
  - 接下来继续执行正常ROI和时间预测ROI。
  - 距上次全图扫描结束不足 `400 ms` 时跳过重复全图扫描。
  - 超过 `400 ms` 后才允许再次执行全图扫描。
- 车辆一旦重新识别，冷却状态立即清零；下一次独立失联仍可即时全图。
- 全图兜底未删除，仅限制连续失败期间的重复频率。
- 性能输出新增：
  - `prediction_success`：预测ROI成功恢复车辆的次数。
  - `full_fallback_success`：全图回退成功恢复车辆的次数。
  - `full_fallback_skip`：因冷却期跳过重复全图扫描的次数。
- 实机失联过程：
  - 首次全图回退失败后，后续窗口分别出现
    `full_fallback_skip=5` 和 `full_fallback_skip=2`。
  - 第二次允许的全图回退成功恢复车辆：
    `full_fallback_success=1`。
  - 失联阶段最低窗口由此前约 `1.6～1.7 FPS` 提升至约 `4.6 FPS`。
  - 恢复后立即回到约 `8～12 FPS`。
- 本轮预测ROI未成功恢复车辆，`prediction_success=0`；保留其低成本兜底，
  但不继续围绕预测倍率派生修改。
- 结论：连续全图扫描造成的低帧率反馈链已被切断，本项完成。

### 6.5 多箱目标全局兜底误配修正

- 状态：已修正，等待复测。
- 多箱测试现象：
  - 首帧识别3箱3目标正确。
  - 前两个箱子推动阶段 FPS 降到约 `3.6～4.5`，`region ≈ 173～218 ms`，符合多个对象ROI叠加后的开销上升。
  - 第一个明确候选事件 `box=1 goal=(8,1)` 成功触发。
  - 随后出现错误：`GLOBAL_GOAL goal=(13,3) evidence=FLOOR` 后，却将 `box=2` 分配到旧目标 `goal=(3,1)`。
- 原因：
  - 全局目标消失兜底的 `g_goal_floor_counts` 会跨目标完成事件残留。
  - `assign_goal_to_missing_box()` 对没有显式候选的丢失箱子只按宽松距离评分，缺少“目标与该箱子运动/位置是否合理”的硬门槛。
- 修正：
  - 新增 `reset_global_goal_evidence()`，任意 `commit_box_goal_match()` 后清空所有全局目标消失计数和trace状态，避免旧证据跨事件复用。
