# 逐飞库函数使用入门：从硬件想到代码

这份笔记不是让你背函数，而是教你拿到一个需求后，怎么判断该用逐飞库里的哪一类函数。

核心思路：

```text
我要控制什么硬件
    ↓
这个硬件需要什么信号
    ↓
去逐飞库对应头文件找函数
    ↓
看工程里有没有类似写法
    ↓
确认引脚、模式、电平和硬件接线一致
```

## 1. 先问：我要控制什么硬件？

不要一开始就问“我要用哪个函数”。先问硬件是什么。

常见硬件和对应信号：

| 你要做什么 | 硬件/对象 | 常用信号 | 逐飞库方向 |
|---|---|---|---|
| 点亮 LED | LED | GPIO 输出 | `zf_driver_gpio.h` |
| 控制电机方向 | 电机驱动 DIR 脚 | GPIO 输出 | `zf_driver_gpio.h` |
| 控制电机速度 | 电机驱动 PWM 脚 | PWM | `zf_driver_pwm.h` |
| 读取轮子速度 | 编码器 | 正交编码器/QTIMER | `zf_driver_encoder.h` |
| 和电脑/蓝牙通信 | 串口模块 | UART | `zf_driver_uart.h` |
| 周期性执行任务 | 定时器 | PIT/TIMER | `zf_driver_pit.h` / `zf_driver_timer.h` |
| 显示文字 | IPS200 屏幕 | SPI + 屏幕驱动 | `zf_device_ips200.h` |
| 读取姿态角速度 | IMU963RA | IMU 设备驱动 | `zf_device_imu963ra.h` |
| 读取电压/模拟量 | 电位器/传感器 | ADC | `zf_driver_adc.h` |
| 读取按键 | 按键 | GPIO 输入 | `zf_driver_gpio.h` |

## 2. 再问：这个硬件需要什么信号？

### 普通开关量：GPIO

如果一个引脚只需要输出高低电平，比如：

```text
高电平 = 开
低电平 = 关
```

那它通常就是 GPIO 输出。

你的工程里电机方向脚就是这样：

```c
gpio_init(C7, GPO, 0, GPO_PUSH_PULL);
gpio_set_level(C7, 1);
```

意思是：

```text
C7 配成普通输出
初始电平为 0
使用推挽输出
之后可以用 gpio_set_level 改成 0 或 1
```

### 连续调速：PWM

如果你不是简单开关，而是想控制“快慢”“亮度”“占空比”，通常用 PWM。

你的工程里电机 PWM 初始化：

```c
pwm_init(PWM2_MODULE0_CHA_C6, 17000, 0);
pwm_set_duty(PWM2_MODULE0_CHA_C6, 5000);
```

意思是：

```text
用 C6 对应的 PWM 通道
频率 17000 Hz
占空比范围通常按 0~10000 理解
5000 约等于 50%
```

### 轮子测速：编码器

如果你要知道轮子转了多少，就看编码器。

你的工程里：

```c
encoder_quad_init(QTIMER2_ENCODER1,
                  QTIMER2_ENCODER1_CH1_C3,
                  QTIMER2_ENCODER1_CH2_C4);

count = encoder_get_count(QTIMER2_ENCODER1);
encoder_clear_count(QTIMER2_ENCODER1);
```

意思是：

```text
C3/C4 接编码器 A/B 相
每次读取这段时间内的脉冲数
读完清零，下一次再重新累计
```

### 电脑/蓝牙通信：UART

如果要发字符串、收命令，通常是 UART。

你的工程里：

```c
uart_write_string(DEBUG_UART_INDEX, "#AI_TUNER_BOOT\r\n");
```

意思是：

```text
通过调试串口发一行字符串给电脑/上位机
```

蓝牙接收是在中断里做的：

```c
void LPUART4_IRQHandler(void)
{
    unsigned char cmd = uart_read_byte(UART_4);
    bt_cmd_handler(cmd);
}
```

意思是：

```text
蓝牙串口收到 1 个字节
把这个字节交给 bt_cmd_handler 处理
```

### 周期任务：PIT 定时器

如果你要“每隔固定时间执行一次”，比如每 5ms 控制一次电机，就用 PIT。

你的工程里：

```c
pit_ms_init(PIT_CH0, 5);
```

然后在中断函数里：

```c
void PIT_IRQHandler(void)
{
    if(pit_flag_get(PIT_CH0))
    {
        pit_flag_clear(PIT_CH0);
        motor_control_5ms();
    }
}
```

意思是：

```text
每 5ms 进入一次中断
清除中断标志
执行一次电机控制
```

## 3. 去哪个头文件找？

逐飞库常用头文件速查：

| 功能 | 头文件 |
|---|---|
| GPIO | `libraries/zf_driver/zf_driver_gpio.h` |
| PWM | `libraries/zf_driver/zf_driver_pwm.h` |
| 编码器 | `libraries/zf_driver/zf_driver_encoder.h` |
| UART | `libraries/zf_driver/zf_driver_uart.h` |
| PIT 定时器 | `libraries/zf_driver/zf_driver_pit.h` |
| 普通定时器 | `libraries/zf_driver/zf_driver_timer.h` |
| ADC | `libraries/zf_driver/zf_driver_adc.h` |
| SPI | `libraries/zf_driver/zf_driver_spi.h` |
| I2C | `libraries/zf_driver/zf_driver_iic.h` |
| IPS200 屏幕 | `libraries/zf_device/zf_device_ips200.h` |
| IMU963RA | `libraries/zf_device/zf_device_imu963ra.h` |
| 蓝牙 CH9141 | `libraries/zf_device/zf_device_bluetooth_ch9141.h` |
| 无线串口 | `libraries/zf_device/zf_device_wireless_uart.h` |

你的 `main.c` 包含了：

```c
#include "zf_common_headfile.h"
```

这个文件又帮你包含了大量逐飞库头文件，所以很多函数可以直接用。

## 4. 看到头文件后看什么？

主要看函数名里的动词：

| 函数名关键词 | 大概意思 |
|---|---|
| `init` | 初始化，通常上电后先调用 |
| `set` | 设置某个状态，比如电平、占空比 |
| `get` | 读取某个值 |
| `read` | 读取数据 |
| `write` | 发送/写入数据 |
| `clear` | 清除计数、标志位 |
| `handler` | 中断或事件处理函数 |
| `show` | 显示到屏幕 |

例如：

```c
gpio_init(...)
gpio_set_level(...)
encoder_get_count(...)
encoder_clear_count(...)
ips200_show_string(...)
uart_write_string(...)
```

你不用背，只要看到函数名，大概能猜出用途。

## 5. 怎么判断推挽输出、上拉、下拉？

这是新手很容易卡住的点。

### 推挽输出

当这个引脚要主动输出明确的高电平和低电平时，用推挽输出。

适合：

```text
LED
电机方向脚
电机使能脚
普通控制脚
SPI 片选 CS
蜂鸣器控制脚
```

你的工程里：

```c
gpio_init(C7, GPO, 0, GPO_PUSH_PULL);
```

因为 C7 是电机方向控制脚，需要主动输出 0 或 1，所以用 `GPO_PUSH_PULL`。

### 开漏输出

开漏一般用于“只主动拉低，不主动拉高”的场景，常见是 I2C。

适合：

```text
I2C 总线
多个设备共享一根线
外部有上拉电阻的特殊总线
```

普通电机方向脚不要乱用开漏。

### 上拉输入 / 下拉输入

按键输入常见。

判断方法看电路：

```text
按键按下接 GND：通常用上拉输入
按键按下接 VCC：通常用下拉输入
```

## 6. 用你项目里的电机控制举完整例子

目标：

```text
控制三轮小车的三个电机
```

硬件需要：

```text
每个电机一个 PWM 控制速度
每个电机一个 GPIO 控制方向
每个轮子一个编码器反馈速度
```

所以要用：

```text
PWM 函数
GPIO 函数
ENCODER 函数
PIT 定时器函数
PID 算法
```

代码路径：

```text
project/user/src/main.c
    初始化电机 IO、PWM、编码器、PIT

project/user/src/isr.c
    PIT 中断每 5ms 调用 motor_control_5ms

project/code/motion_control.c
    读取编码器
    计算目标轮速
    PID 计算输出
    设置 GPIO 方向和 PWM 占空比
```

对应函数：

```c
gpio_init(...)
pwm_init(...)
encoder_quad_init(...)
pit_ms_init(...)
encoder_get_count(...)
encoder_clear_count(...)
pwm_set_duty(...)
gpio_set_level(...)
```

这就是从“我要控制电机”一步步推到“我要用这些库函数”的过程。

## 7. 每次写新功能前的检查清单

以后你想加一个功能，就按这个清单走：

```text
1. 我要控制/读取什么硬件？
2. 它接在哪个引脚？
3. 它需要 GPIO、PWM、UART、SPI、I2C、ADC、编码器里的哪一种？
4. 去对应的 zf_driver_xxx.h 或 zf_device_xxx.h 找函数。
5. 先找 init 函数。
6. 再找 set/get/read/write/show 函数。
7. 搜工程里有没有类似写法。
8. 对照引脚分配表，确认引脚写对。
9. 对照硬件电路，确认推挽/上拉/下拉/初始电平写对。
10. 先写最小测试，不要一上来写复杂逻辑。
```

## 8. 最小测试思维

新手最重要的习惯：

```text
先让一个硬件单独工作，再组合进大程序。
```

比如：

```text
先让 LED 闪
再让 PWM 输出
再让一个电机转
再读一个编码器
再做 PID
最后再做整车运动
```

不要一上来就改整车控制逻辑。这样出问题时，你不知道是引脚错、函数错、PID 错，还是硬件接线错。
