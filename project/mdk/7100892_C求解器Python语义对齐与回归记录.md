## 7100891故障根因

1. `micro_scheduler.c`和`push_bfs.c`的最小堆弹出操作使用旧根节点参与比较，未用末节点正确下沉，搜索顺序可能错误。
2. 已经到达目标并按游戏规则消失的箱子，在C调度和Action生成中仍被当作永久障碍。
3. 微任务调度只检查车辆能否到达箱后，没有检查箱子的整段推进通道是否被另一个未完成箱子占据。
4. 旧回退排列只产生4个不同顺序，未覆盖3个箱子的全部6种顺序；代价统计也错误使用最终车辆位置。
5. 求解器没有在报告成功前对最终Action做逐格物理语义回放。

故障图为Python项目`maps_import/map2.txt`，实车起点`(2,7)`。7100891会先把box2推到`(10,6)`，随后又试图把box1推入同一格，执行层因此正确报`PUSH_MAP_MISMATCH`。

## 7100892修改

- 修复两个最小堆的下沉逻辑，并加入确定性同代价排序。
- 微任务搜索容量由128提升到512。
- 箱子完成后立即从车辆和箱子的障碍集合移除。
- 每个候选推箱微任务先逐格检查边界、墙、未完成箱子和提前进入目标。
- 回退改为完整枚举`3!`个目标分配乘`3!`个箱子执行顺序，最多36组。
- 回退代价改为实际车辆BFS步数加实际推箱步数。
- 禁止静默截断超过`MAX_WP`的路径；不能完整表达时直接拒绝候选。
- 新增最终Action语义校验：四邻域、逐格、车辆不穿墙/箱、箱子不撞墙/箱、目标消失语义、最终箱子和目标全部清空。
- 串口新增：

```text
PLAN_CHECK ok=1 code=OK action=255 step=255 cell=(255,255) policy=GRID4+BOX_DISAPPEAR
```

只有`ok=1 code=OK`才允许计划成为有效计划。
