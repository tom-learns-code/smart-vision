## 解锁型炸点的定义
对一个"直达 push_box_bfs 推不动"的 (box,goal) 对，枚举**引爆中心 c**(可以是空格!)，
若炸掉 `get_walls_in_3x3(c, walls)` 后的新墙态下 push_box_bfs(box,goal,...) 变 OK，则 c 是解锁该对的炸点。
还需验证 c 可由某炸弹推达(炸弹推到空格c引爆，或推到墙体c引爆)。

## 性能难点（关键）
全枚举所有引爆中心 = 306次 push_box_bfs = **1724ms**（超红线3.4倍）。
矩形剪枝(box-goal矩形expand=2附近墙的相邻空格) = 171次 = **970ms**（仍超）。
push_box_bfs 单次约5-6ms。**必须把每对的候选引爆点从几十个压到几个**，靠"不跑R2的轻量预筛"先淘汰。

## 关键 API（algorithms/path_search.py，不import algorithms模块，安全）
- `push_box_bfs(box, goal, walls, w, h, obstacles, initial_car_pos=None, max_steps=200)` → (steps,turns,path) or None。带R2车可达性(转向时验车能到推动站位)。
- `push_bomb_bfs(bomb, wall, walls, w, h, obstacles, car_start=None)` → (steps,turns,path) or None。
- `core.map_analysis.get_walls_in_3x3(center, walls)` → 中心3x3内的可破坏墙集(非边界墙)。
- `core.map_analysis.get_walls_in_rect(box, goal, walls, expand=2)`、`is_boundary_wall(wall,w,h)`、`analyze_connectivity(w,h,obstacles,exempt_positions)`。
- `core.bfs.bfs_shortest_path(start, target, blocked, w, h)` → path or None（轻量，可用于车可达预筛）。
- `core.distance.manhattan_distance(a,b)`。

## blast_select.py 现状
preplan_blasts 产两类候选(都以墙格为引爆中心):
1. `_find_region_boundary_walls`: 4邻分属≥2连通分量的内部墙。
2. 死锁元素救援 + 连锁救援链 DFS(max_depth=3)。
返回 `blast_candidates: [{wall, benefit:{p0a,p0b,p0c,p1a,p1b,p2}, chain_depth, unlocks_bomb, score}, ...]`。
assignment.py 的 `_compute_bomb_candidates` 消费 blast_candidates（取 c['wall'] 作引爆点 + box-goal矩形墙），
`_compute_bomb_score` 对每面候选墙×每个炸弹算炸后推箱代价。

## 你要实现的预筛剪枝策略（每个agent一种，下面是建议方向，可自行优化）
目标: 每个"直达推不动"的对，产出 ≤3-5 个高质量解锁引爆点候选，总 push_box_bfs 调用 <30次，step4 总耗时 <0.3s(留余量)。

预筛思路（不跑R2的轻量判断）:
- **连通分量预筛**: 炸某中心c后，box和goal是否进入同一连通分量(analyze_connectivity)。不同分量直接淘汰，无需R2。
- **车可达BFS预筛**: 炸后车能否到达goal的推入站位(bfs_shortest_path轻量)。
- **引爆点定位**: 只在"卡住箱推进的那面墙"附近找引爆中心——先用一次push_box_bfs找箱推到哪卡住(路径末端)，在卡点附近枚举引爆中心，而非全图/全矩形。
- **炸弹可达过滤**: 引爆中心c必须能被某炸弹推达(push_bomb_bfs)，先过滤不可达的c。
- **top-K**: 预筛打分后只对top-3~5个c跑完整R2 push_box_bfs确认。
