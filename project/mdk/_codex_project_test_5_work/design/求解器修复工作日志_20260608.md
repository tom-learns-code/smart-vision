## 二、已修复（5 处，按修复顺序）

### 修复 1：模拟器幽灵碰撞（用户最初报的现象）
- **文件**：`run_sim.py`（约 543 行）、`run_sim_debug.py`（约 636 行）
- **根因**：箱子到目标后加入 `completed_boxes`（不再进主物理循环），但仍留在 `boxes` 列表、坐标残留在目标点。而 Action 切换时的 `_separate` 重叠分离循环直接遍历整个 `boxes`，没过滤 `completed_boxes`，把"幽灵箱子"当实体障碍，后续箱子/车经过已消失目标点时被顶开 → 突然偏移。
- **改动**：`_separate` 循环加 `completed_boxes` 过滤（car-vs-box 跳过已完成；box-vs-box 双方都跳过），与主物理循环的 `active_boxes` 过滤口径一致。
- 详见 memory（未单独建文件，见本文档）。

### 修复 2：blast_refine 降级丢炸弹（第一层根因）
- **文件**：`algorithms/blast_refine.py`（约 661-720 行，"基础重算"段）
- **根因**：降级机制判断某对能否「搭别的对炸墙便车、省掉自己炸弹」时，用了**包含它自己炸墙的合并墙态 all_walls**（循环论证），把需炸弹对误降级成直达对，清掉 `uses_bomb`/`bomb_plan`。
- **下游连锁**：步骤6直达分支推箱失败→只打 WARN 塞空 plan→模拟器 `pf.is_done()` 只看 Action 跑完不看箱子是否到目标→显示「全部完成」但实际漏推箱子（=用户报的第二个现象）。
- **改动**：降级判定改用 `walls_no_self = all_walls | get_walls_in_3x3(自己的wall/chain墙)`（把自身炸墙加回去，只保留别的对炸墙增益），仅当不靠自己炸弹也可达才降级，否则保留 bomb_plan。
- memory：`bug-blast-refine-self-bomb-downgrade`

### 修复 3：push_box_bfs 不验车可达 / 死口袋（R2）
- **文件**：`algorithms/path_search.py`（`push_box_bfs` 方向转移处，约 140-180 行）
- **根因**：推箱搜索每步只静态检查「车站位不是墙」，从不验证车能否真走到。选中了车进不去的死口袋站位（如 map3(4) 的 (13,9) 三面被墙+箱封死），导致步骤7 scheduler 的 car_bfs 到不了 → 整体失败。
- **改动**：方向转移时，若车需换位（`car_pos != car_after_prev`，即推动方向改变），用 `car_bfs`（=bfs_shortest_path）验证车能否从上一步位置走到新推动站位（障碍含当前箱子位置 pos），走不到则排除该推法。同向连续推不检查（车自然跟进）。
- **效果**：map4(1) FAIL→OK；map3(4) 死口袋解除。
- memory：`bug-push-box-bfs-car-reachability`

### 修复 4 & 5：verify_actions 工具缺陷（不消除到达目标的箱子）
- **文件**：`run_solver.py` 的 `verify_actions`（walkable 约 112 行、push_box 完成约 165 行、终态检查约 209 行、新增 last_push_step 预扫描约 110 行）
- **根因**：箱子到目标后 verify 不消除它（仍在 box_pos 占位），导致后续箱子「借道已完成箱子的目标格」被误报 blocked。这是**工具缺陷不是算法错**（真实模拟器有 completed_boxes 消除机制）。
- **改动**：
  - 预扫描每个 box 的 `last_push_step`（最后一次 push_box 动作索引）。
  - 箱子**仅当在它最后一段推动后落在 goal** 才置 `box_pos[bid]=None`（消失）；中途借道经过目标格不算完成（避免误消失）。
  - `walkable` 中 `bp is not None and bp == pos` 才算阻挡。
  - 终态检查 `bp is None` 视为已完成跳过。
- **效果**：map3(1)、map2(1)、map4(4)、map5(1) 从「假失败」变真 OK。
