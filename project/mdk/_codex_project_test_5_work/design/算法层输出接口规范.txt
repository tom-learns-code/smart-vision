================================================================================
  算法层输出接口规范 v1.0
  2026-05-28
================================================================================

本文档定义算法层需要输出给中间层（路径-运动转换层）的数据格式。
中间层拿到这个输出后，逐条执行，将动作转换为速度指令 (vx, vy, ω) 发给全向控制层。

================================================================================
一、总体结构
================================================================================

算法层的最终输出是一个 Action 列表：

    [Action_1, Action_2, Action_3, ...]

按执行顺序排列。中间层从第一条开始顺序执行，每条完成后再执行下一条。

================================================================================
二、Action 类型定义
================================================================================

共4种动作类型：

    类型码           含义                        到达条件
    ──────────────────────────────────────────────────────────────
    free_move        自由移动（不推任何物体）       车到达 target 位置
    push_box         推箱子                        箱子停在目标格上
    push_bomb        推炸弹                        炸弹停在目标墙体格上
    wait             等待                          计时到达 duration

================================================================================
三、Action 字段详解
================================================================================

3.1 公共字段（所有类型都有）
────────────────────────────────────────────────

    字段          类型          说明
    ──────────────────────────────────────────────────
    type          str           动作类型: "free_move" | "push_box" | "push_bomb" | "wait"
    target        (int,int)     目标网格坐标。wait类型下无意义，填 null
    theta         float|null    目标朝向（弧度）。null 表示不需控制朝向，保持任意朝向即可。
                                非null时中间层会在移动同时旋转到该角度。

3.2 free_move 特有字段
────────────────────────────────────────────────

    字段          类型          说明
    ──────────────────────────────────────────────────
    waypoints     [(float,float)]|null
                                第二阶段使用。自由段的连续路径点序列（世界坐标）。
                                第一阶段填 null，中间层走直线到 target。
                                第三阶段可包含弧线/斜线路径点。
    narrow_passage  bool        第三阶段使用。此段是否经过窄通道（两侧至少一侧是可动物体）。
                                第一阶段填 false。

3.3 push_box 特有字段
────────────────────────────────────────────────

    字段          类型          说明
    ──────────────────────────────────────────────────
    push_meta     dict          推动参数
      ├─ box_id       int       箱子编号（对应世界状态中的箱子索引）
      ├─ box_start    (int,int) 箱子起始网格坐标
      ├─ box_target   (int,int) 箱子目标网格坐标（推完后箱子应在的位置）
      └─ push_dir     str       推动方向: "UP" | "DOWN" | "LEFT" | "RIGHT"
    narrow_passage  bool        第三阶段使用。同上。

    注意：target 字段表示推完后车自己站的网格位置。

3.4 push_bomb 特有字段
────────────────────────────────────────────────

    字段          类型          说明
    ──────────────────────────────────────────────────
    push_meta     dict          推动参数
      ├─ bomb_id      int       炸弹编号
      ├─ bomb_start   (int,int) 炸弹起始网格坐标
      ├─ bomb_target  (int,int) 炸弹目标网格坐标（炸弹停在墙体格上）
      ├─ wall_target  (int,int) 将被炸毁的墙体网格坐标
      └─ push_dir     str       推动方向: "UP" | "DOWN" | "LEFT" | "RIGHT"
    narrow_passage  bool        第三阶段使用。同上。

3.5 wait 特有字段
────────────────────────────────────────────────

    字段          类型          说明
    ──────────────────────────────────────────────────
    duration      float         等待时长（秒）
    reason        str           等待原因: "bomb_explosion" | "stabilize" | ...

================================================================================
四、完整示例
================================================================================

以下是一个"先推炸弹炸墙，再推箱子到目标"场景的完整输出：

[
    # === 第1步：走到炸弹的推动位置 ===
    {
        "type": "free_move",
        "target": (5, 3),
        "theta": null,
        "waypoints": null,
        "narrow_passage": false
    },

    # === 第2步：推炸弹到墙体位置 ===
    {
        "type": "push_bomb",
        "target": (5, 2),
        "theta": null,
        "push_meta": {
            "bomb_id": 0,
            "bomb_start": (5, 4),
            "bomb_target": (5, 1),
            "wall_target": (5, 1),
            "push_dir": "UP"
        },
        "narrow_passage": false
    },

    # === 第3步：等待炸弹爆炸 ===
    {
        "type": "wait",
        "target": null,
        "theta": null,
        "duration": 0.5,
        "reason": "bomb_explosion"
    },

    # === 第4步：走到箱子的推动位置（经过被炸开的通道） ===
    {
        "type": "free_move",
        "target": (7, 6),
        "theta": null,
        "waypoints": null,
        "narrow_passage": true
    },

    # === 第5步：推箱子到目标 ===
    {
        "type": "push_box",
        "target": (8, 6),
        "theta": 0.0,
        "push_meta": {
            "box_id": 0,
            "box_start": (6, 6),
            "box_target": (10, 6),
            "push_dir": "RIGHT"
        },
        "narrow_passage": false
    }
]

================================================================================
五、阶段演进说明
================================================================================

            第一阶段            第二阶段              第三阶段
            ─────────           ──────────            ──────────
waypoints   填 null             自由段填连续路径点     第二阶段基础上
                                推动段填 null          增加窄道/弧线

narrow_     填 false            填 false              根据场景标记
passage                                                true/false

theta       大部分填 null       填识别/推箱所需的      进一步优化
                                朝向

push_meta   基础字段            不变                   不变

说明：第一阶段只关注跑通基础链路，waypoints 和 narrow_passage 均可留默认值。
      第二阶段算法层出口加路径平滑，自由段填充 waypoints。
      第三阶段标记窄通道，并在需要时输出带朝向要求的动作。


================================================================================
六、坐标系统
================================================================================

- 算法层统一使用网格坐标（格子索引）
- 中间层负责网格坐标 → 世界物理坐标的转换
- 世界坐标原点、网格大小等参数由中间层从 config 获取
- theta 使用标准弧度制，0 = 正右方，π/2 = 正下方（参考比赛场地坐标系）

================================================================================
七、责任边界
================================================================================

  算法层负责:                     中间层负责:
  ──────────                      ──────────
  · 决定"做什么、按什么顺序"      · 导航到每个 target
  · 计算推动方向和路径步数         · 网格坐标→物理坐标转换
  · 标记窄通道                     · 位置/朝向闭环控制
  · 输出 Action 序列               · 到达判定
                                   · 执行环境偏差检测（第三阶段）
                                   · 需要时回调算法层重规划（第三阶段）
