# 炸点规划+分配重构 — 设计简报 (共享给方案设计 agent)

## 项目
车推箱子算法求解器 project_test_4.4, 第21届(2026)智能车竞赛AI视觉组。
**核心定位**: 算法层是重点, 模拟器只是把算法输出跑出来看的可视化工具。

## 8步求解管线 (algorithms/)
scan_map → compare_connectivity(2b) → analyze_channels(3) → preplan_blasts(3.5) → solve_assignment(4) → refine_blast_points(5) → generate_pair_plans(6) → schedule_pair_plans(7) → generate_actions(8)
入口: `python run_solver.py [map]` (自带 verify_actions 网格回放验证)

## 文件分工
- blast_select.py (步3.5 preplan_blasts): 炸点预规划。当前只产两类候选: (a)区域桥接墙(_find_region_boundary_walls要求墙4邻分属≥2连通分量) (b)死锁元素救援。**只把墙格当引爆点**, 只评"连通桥接/静态死锁"收益。
- assignment.py (步4 solve_assignment): 全排列×炸弹mask穷举(n!×2^n, n=3时48组合)。每组合算评分向量 vec=(可行,-unsolvable,-总步数,-转向,未用弹,score)。**已有top-5合并墙态可行性回验(572-617行)**, 但回验用浅层_bfs_push_box(不验车可达), 且逐对独立(不检查多箱路径互斥)。
- path_search.py (步6 generate_pair_plans): 用push_box_bfs(**带R2车可达性检查**, 转向时car_bfs验证车能到推动站位)生成MicroTask。直达对/单炸弹对/链分支三种。其post_obs已豁免其他箱子(会被推走)。
- scheduler.py (步7): Dijkstra状态空间搜索, 状态=(car_xy,各pair已完成task数,last_dir)。动态墙态推导+动态障碍(推过的箱成新障碍)。返回None=搜不到全完成态。

## 关键数据结构
- PairPlan: pair_id+box/goal+bomb_tasks+pre/post_box_tasks+is_direct+is_chain+chain+blast_clears
- MicroTask: task_type(push_box/push_bomb)+obj_start/end+push_dir+n_steps+car_target+car_end
- 炸弹机制: 推炸弹进墙体, 3x3范围炸毁可破坏墙(非边界墙)。bomb_id=len(boxes)+bomb_idx。**炸弹可推到空格引爆, 用3x3溅射炸掉斜对角的墙**(关键!当前算法不利用这点)。

## 性能红线 (极重要)
比赛计时。**整个算法计算 <0.5s, 硬上限1s**。当前基线: 总耗时最高222ms, 大头step4分配最高181ms(全排列×mask)。step5/6/7/8都<35ms。任何带R2(car_bfs)的验证只能放在top-5回验层(跑≤5次), **绝不能进48组合内层循环**否则爆表。push_box_bfs(带R2)单次约几ms。

## 三张失败图根因 (已深挖钉死, 理论全部3/3可解)

**统一病根**: assignment用浅层_bfs_push_box选配对, 选出的对用真实push_box_bfs(带R2)验证后大量FAIL:
- map8: 3对里2对FAIL(车进不去). box(2,9)→goal(2,4)被墙+box(3,8)围在左下口袋; goal(9,1)原墙态无任何推入方向(必须炸墙造口)。
- map5(4): 3对里2对FAIL. box(2,3)→g(12,6)和box(2,5)→g(13,5)的解锁炸点**是同一个**(炸(12,7))——一弹解锁多对!且两箱被规划走同一走廊(2,9)→(11,9)→(11,7)对撞致scheduler死锁。
- map3(4): box(2,9)→g(13,7) FAIL。需把炸弹推到**空格(11,9)引爆**, 3x3溅射炸(12,9)解锁goal(13,7)从下推入的车站位(13,9)(原(12,9)墙把(13,9)封成死口袋)。用户录播recorded_001.json证明3/3可解。

## 四个纠缠子问题
1. **可行性脱节**: assignment可行性判断(浅_bfs_push_box)比path_search(带R2)浅 → 选出推不动的对 → 空plan → scheduler崩(SOLVEFAIL)或漏推(VERIFAIL)。
2. **解锁型炸点缺失**: 需"炸弹推到空格引爆、3x3溅射炸开通路/解锁死口袋车站位"。当前炸点只认墙格、只评连通收益。
3. **一弹解锁多对(跨对依赖R1)**: 一次炸墙能同时解锁多个箱的路径, 但assignment把每个(box,goal,bomb)当独立配对评分, 无"一弹利好多对"概念。
4. **多箱路径互斥**: 多箱被规划走重叠走廊会在scheduler对撞死锁。
