# project_test_5 算法修复与 C 移植规划

## 本轮目标与结论

- 规则目标：炸弹只能被推入墙格引爆，只清除该墙格周围 3x3 内的墙；箱子、目标点等其他元素不受爆炸影响。
- 识别目标：严格执行 N-2。若箱子与目标各有 N 个，则分别只观察 N-1 个；剩余编号由一一对应关系推导。
- 路径目标：观察前必须转向目标；P2 不得复用已经进入指定目标并退场的箱子；结束后车辆返回 `(1,6)` 或 `(14,6)` 中可达且更近的基地。
- 回归结论：除约定例外 `map7.txt` 外，16 张地图全部通过独立规则回放；共测试 79 组箱子/目标编号排列，0 失败。
- `map7.txt`：P1 立即返回无解，不是超时。本轮按约定保留为唯一未解决地图。

## 已修复的根因

1. **N-2 被写死为三箱场景**
   - 改为按实际箱子/目标数量计算观察配额。
   - 1+1 地图观察 0+0；2+2 地图观察 1+1；3+3 地图观察 2+2。
   - 开局视野、TSP 观察和贪心补观察都受同一配额约束，不能多读。

2. **观察动作未强制朝向**
   - `observe` 动作先按 `theta` 转向。
   - 朝向误差进入 5 度后才开始计时；偏出范围会清空观察停留计时。
   - 解决车辆背对箱子/目标仍被判定为已观察的问题。

3. **编号推导不严格**
   - 已知编号必须唯一。
   - 箱子数和目标数必须相等。
   - N-2 后箱子侧和目标侧最多各剩一个未知编号，并做确定性补全。
   - 最终箱子编号集合和目标编号集合必须完全一致。

4. **P2 固定按三箱排列**
   - 1 箱只尝试 `[0]`。
   - 2 箱尝试 `[0,1]`、`[1,0]`。
   - 3 箱尝试全部 6 种排列。
   - 修复 `map6` 中跳过不存在箱子仍被误判为成功的问题。

5. **已完成箱子被再次复用**
   - P2 转换器接收每个箱子的指定目标。
   - 箱子到达其指定目标后立即退场，不再作为障碍或可推动对象。
   - 修复 `map11` 中完成箱被后续路径再次推动的问题。

6. **P2 结束点不符合基地约束**
   - Dijkstra 成功路径末尾增加返回基地路径。
   - 在 `(1,6)`、`(14,6)` 中选择当前墙态下可达且更近者。

7. **旧验证器可能假通过**
   - 新增 `strict_regression.py`，使用独立状态机逐步回放，不调用求解器的内部判定。
   - `verify_paths.py` 保留原文件名，但已改为严格回归入口。
   - 旧 `verify_actions()` 也拒绝空格引爆、无活炸弹引爆和炸弹位置不匹配。

## 严格回放覆盖范围

严格回放会检查：

- P1 每一步移动、推箱、推炸弹、碰撞和边界；
- 爆炸中心必须是当前仍存在的原始内部墙，且每个中心只能使用一次；
- 3x3 只删除墙，其他元素状态不变；
- N-2 观察数量、观察对象索引、观察方向与 `theta`；
- 编号推导及箱子到目标的一一映射；
- P2 的行走、推箱、碰撞、箱子退场和禁止复用；
- 所有箱子最终完成；
- 车辆最终返回两个基地之一；
- `PathFollower` 未对准观察角时不得完成观察。

## 后续 C 移植计划（本轮不改 C）

### 1. 冻结 Python 为参考实现

- 为每张地图导出 P1 原始动作、观察掩码、推断编号、P2 动作和最终基地。
- 参考结果必须带地图哈希和规则版本，防止以后拿错地图或旧结果对拍。
- Python 严格回放器继续作为唯一规则裁判，C 求解器不得自证正确。

### 2. 按语义模块移植，不按文件整块覆盖

- **P1 观察配额**：移植动态 N-2 配额、掩码限额和完成条件。
- **观察执行**：C action 增加观察类型、对象索引、方向和目标角；中间层必须先转向并稳定，再触发识别。
- **编号解析**：移植唯一性检查、最多一对未知和确定性补全。
- **P2 排列**：排列数量必须由 `box_count` 决定，禁止固定访问第三个箱子。
- **箱子生命周期**：到达指定目标后从活动箱集合和障碍集合移除。
- **炸弹规则**：最后一步只能进入当前墙格；爆炸只改变墙掩码；拒绝空爆。
- **终点约束**：P2 完成后追加返回最近可达基地。

### 3. 先做 PC 主机版 C 对拍

- 把待移植 C 求解器编译为 PC 命令行程序，不先下载 MCU。
- 输入与 Python 相同的 16 张地图和 79 组编号排列。
- C 输出统一为逐格动作及观察/爆炸元数据，再交给 Python 严格回放器验证。
- 门槛：除 `map7` 外 16/16、79/79 通过；任何超时、动作溢出或非法元数据都算失败。
- 同时记录最大静态内存、队列峰值、动作数和每图耗时，再决定 DTCM/OCRAM 放置。

### 4. 接入现有 MCU 中间层

- 视觉全图帧先转换为统一的 16x12 地图；四条边界在视觉层固定为墙。
- 求解期间电机保持锁定，求解器只在主循环运行，不能放进 ISR。
- 中间层把复合路径拆成逐格动作；`N` 单步一格，`A` 连续执行但每格停车等待视觉更新。
- 观察 action 的完成条件必须是“姿态已对准 + 稳定时间满足 + 收到对应识别结果”，不能只靠等待时间。
- 推箱和推炸弹期间以编码器+IMU 为主，视觉只在格间停车后做低频位置校正，避免视觉延迟直接干扰闭环。
- 一轮结束后请求全图复核：车中心最近格强制视为车并忽略该格的元素分类；若仍有未完成箱子，再进入受控重规划。

### 5. 实车验收顺序

1. 菜单 dry-run：只打印 P1/P2 逐格动作，不解锁电机。
2. 观察动作：逐个验证朝向、识别对象和 N-2 停止条件。
3. 无炸弹地图：单步 `N` 跑完整路径。
4. 无炸弹地图：自动 `A`，每格停车并等待视觉校正。
5. 单炸弹地图：只执行到引爆并人工确认墙态更新。
6. 完整炸弹地图：单步后自动。
7. 结束全图复核与一次受控重规划。

只有主机 C 对拍全绿后才进入第 1 步，避免把算法错误和车辆定位误差混在一起调。
