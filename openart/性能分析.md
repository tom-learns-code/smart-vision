## 每帧计算量拆解

### 1. 建图 `build_current_map()` — 主要瓶颈

```
网格: 16列 × 12行 = 192 个格子
SAMPLE_MODE=2: 每格取 3×3 = 9 个像素点做均值
总采样点数: 192 × 9 = 1728 像素
```

每个采样点调用链：`img.get_pixel()` (C层) → `rgb_to_lab()` (**纯 Python 浮点**)

`rgb_to_lab()` 每调用一次的操作量：

| 步骤 | 操作 | 数量 |
|------|------|------|
| RGB → 归一化 | float 除法 `/255.0` | 3 |
| Gamma 展开 | `** 2.4` (pow!) | 3 |
| 线性化 | 乘法 + 加法 | 9乘 + 6加 |
| XYZ → 归一化 | float 除法 | 3 |
| XYZ → LAB | `_lab_xfer_f()` 含 `** (1/3)` (pow!) | 3 |
| LAB 输出 | 乘法 + 减法 | 3乘 + 3减 |
| **合计** | **6 次 pow() + ~30 次浮点运算** | |

在 MicroPython 解释器下，`pow()` 即使走 C 数学库 + FPU 硬件，加上 Python 调用开销，单次仍需**数十微秒**。

### 2. 小车追踪 `find_player()` (局部搜索，通常命中)

```
搜索范围: PLAYER_SEARCH_RING=1 → 3×3 = 9 格
每格约 36×35 ROI像素 → 搜索区域约 108×105 像素
步长: PLAYER_SCAN_STEP_MODE2=4
实际采样点: (108/4) × (105/4) ≈ 27×26 ≈ 700 像素
```

每采样点: `get_pixel()` + `rgb_to_lab()` + 色域区间比较 (6-7条条件)

### 3. 全图搜索 `find_player_full_frame()` (仅在局部失败时触发)

```
搜索区域: ROI 578×418 像素
步长=4 → (578/4) × (418/4) ≈ 144×104 ≈ 15,000 像素
```

全图搜索的计算量是局部搜索的 **~20 倍**，一旦触发帧率会严重下跌。

## 帧率估算

### 正常路径（局部追踪命中）

| 阶段 | 操作 | 估算耗时 |
|------|------|---------|
| `sensor.snapshot()` | VGA 帧捕获 (C层 DMA) | ~8–12ms |
| `build_current_map()` | 1728 次 Python `rgb_to_lab()` | **~80–150ms** |
| `find_player()` 局部搜索 | ~700 次 Python `rgb_to_lab()` | ~30–50ms |
| 串口发送 | 几十~几百字节 | <1ms |
| **合计** | | **~120–210ms** |

> **预估帧率: 约 5–8 FPS**

### 降级路径（局部失败 → 全图搜索）

全图搜索额外增加 ~500ms+，帧率暴跌至 **1–2 FPS**。若再触发 `PLAYER_FIND_EXTRA_SNAPSHOTS=2` 次重拍，最坏情况下近 **2 秒** 才能恢复。

## 性能问题总结

| 问题 | 严重度 | 影响 |
|------|--------|------|
| `rgb_to_lab()` 纯 Python 浮点实现 | 🔴 致命 | 吃掉 80% 帧时，6 次 `pow()` 每调用 |
| 每帧必跑 `build_current_map()` | 🟠 高 | 建图 1728 次 LAB 转换，即使追踪模式下不需要新地图 |
| `SKIP_GRID_ON_MODE2` 未生效 | 🟠 高 | 变量定义了但主循环没用到，注释里的设计意图未实现 |
| `SAMPLE_MODE=2` 九点采样 | 🟡 中 | 比单点采样多 9 倍计算量 |
| `PLAYER_FIND_EXTRA_SNAPSHOTS=2` | 🟡 中 | 丢车后最多重拍 2 次，每次都是全图搜索，雪上加霜 |

## 优化方案（按收益排序）

### 🔴 最高优先级：消除 Python 浮点 `rgb_to_lab()`

**方案 A — 256 级整数查找表（推荐）**

预计算 R、G、B 各 256 级对应的 LAB 值，存为 3 个 `bytearray` 查表数组（各 256 项）。`sample5_lab()` 变成：
```python
def sample5_lab_fast(img, x, y):
    # ... 取像素 ...
    L = L_table[r]
    A = A_table[g]  # 注意: 实际上 LAB 由 RGB 三者决定，不能完全独立查表
    B = B_table[b]
```
> ⚠️ 注意: RGB→LAB 是三维→三维映射，不能简单拆成三个一维表。需要做 256³ ≈ 16M 条目（太大），或者降精度到 32³ = 32K 条目（可放入 2MB SRAM）。

**方案 B — 用 OpenMV 内置函数替代**

把 LAB 色域判定转回 RGB 阈值，用 `image.find_blobs()` 在 C 层完成分类：
```python
# 示例: 在 RGB 空间定义阈值
wall_threshold = [(L_min, L_max, A_min, A_max, B_min, B_max), ...]
blobs = img.find_blobs(wall_threshold, roi=ROI)
```
一次 C 调用替代 1728 次 Python 循环，帧率直接跳到 **30+ FPS**。

**方案 C — `@micropython.native` 装饰器**

```python
@micropython.native
def rgb_to_lab(r, g, b):
    ...
```
约 2× 加速，治标不治本，但零成本可试。

### 🟠 高优先级：真正实现 `SKIP_GRID_ON_MODE2`

在主循环中（约行 756），当仅需做 POS_UPDATE（非全图请求）时跳过建图：
```python
if need_full_map or not SKIP_GRID_ON_MODE2:
    out = build_current_map(img)
else:
    out = last_map  # 复用上一帧地图
```
追踪模式帧率直接翻倍。

### 🟡 中优先级：降采样

- `SAMPLE_MODE = 1` → 建图快 9 倍
- `PLAYER_SCAN_STEP_MODE2` 从 4 调到 6~8 → 追踪采样量减半
- 降分辨率到 QVGA (320×240)，ROI 等比缩小 → 所有采样量减至 1/4

### 🟢 低优先级：小修小补

- `IDLE_UART_SLEEP_US = 0` → 忙等，消除 100µs 休眠延迟
- 把 `_SAMPLE5_DXY` 从 9 点缩减到 5 点（十字采样）→ 建图采样量减 ~44%
- `PLAYER_SKIP_SAMPLES_IN_LASTMAP_BOX = True` → 消除箱子对质心的干扰，间接减少丢车导致的昂贵全图搜索
